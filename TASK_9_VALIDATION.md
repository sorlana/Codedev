# Валидация полей перед генерацией плана задач

## Задача
Добавить проверку заполненности всех обязательных полей (Requirements, Design, Tasks) перед генерацией плана задач.

## Реализация

### 1. Валидация в openTaskPanel()
**Файл**: `wwwroot/app.js`

Добавлена проверка перед созданием плана:

```javascript
async function openTaskPanel() {
    // Проверка наличия диалога
    if (!currentDialogueId) {
        alert('Выберите диалог');
        return;
    }
    
    // Проверка принадлежности к группе
    const dialogue = dialogues.find(d => d.id === currentDialogueId);
    if (!dialogue || !dialogue.dialogueGroupId) {
        alert('Диалог не принадлежит ни одной группе');
        return;
    }
    
    const group = dialogueGroups.find(g => g.id === dialogue.dialogueGroupId);
    if (!group) {
        alert('Группа диалогов не найдена');
        return;
    }
    
    // Валидация заполненности полей
    const missingFields = [];
    
    if (!group.requirements || !group.requirements.trim()) {
        missingFields.push('Требования (requirements.md)');
    }
    
    if (!group.design || !group.design.trim()) {
        missingFields.push('Проектирование (design.md)');
    }
    
    if (!group.tasks || !group.tasks.trim()) {
        missingFields.push('Задачи (tasks.md)');
    }
    
    if (missingFields.length > 0) {
        const fieldsList = missingFields.join('\n• ');
        alert(`Для генерации плана необходимо заполнить следующие поля:\n\n• ${fieldsList}\n\nОткройте контекст группы и заполните все поля.`);
        return;
    }
    
    // Продолжаем создание плана...
}
```

```javascript
async function checkAndShowTasksButton() {

    // Проверяем заполненность ВСЕХ полей
    const hasRequirements = group.requirements && group.requirements.trim();
    const hasDesign = group.design && group.design.trim();
    const hasTasks = group.tasks && group.tasks.trim();
    
    if (hasRequirements && hasDesign && hasTasks) {
        // Все поля заполнены - проверяем наличие плана
        // Показываем кнопку только если плана нет
    } else {
        // Не все поля заполнены - скрываем кнопку
        tasksButton.style.display = 'none';
    }
}
```

## Поведение

### Сценарий 1: Все поля заполнены
1. Пользователь заполняет Requirements, Design, Tasks
2. Сохраняет контекст группы
3. Кнопка "Сгенерировать план" появляется
4. При клике на кнопку план создается

### Сценарий 2: Не все поля заполнены
1. Пользователь заполняет только 1-2 поля из трех
2. Сохраняет контекст группы
3. Кнопка "Сгенерировать план" НЕ появляется
4. При попытке создать план (если кнопка была видна ранее) показывается сообщение с перечислением незаполненных полей

### Сценарий 3: Попытка создать план без заполнения
1. Пользователь нажимает кнопку "Сгенерировать план"
2. Система проверяет заполненность полей
3. Если не все поля заполнены - показывается alert:
   ```
   Для генерации плана необходимо заполнить следующие поля:
   
   • Требования (requirements.md)
   • Проектирование (design.md)
   • Задачи (tasks.md)
   
   Откройте контекст группы и заполните все поля.
   ```
4. План НЕ создается

### Сценарий 4: Частичное заполнение
1. Пользователь заполняет только Requirements и Design
2. При попытке создать план показывается:
   ```
   Для генерации плана необходимо заполнить следующие поля:
   
   • Задачи (tasks.md)
   
   Откройте контекст группы и заполните все поля.
   ```

## Проверяемые поля

1. **Requirements (requirements.md)**
   - Описание требований к проекту
   - Функциональные и нефункциональные требования

2. **Design (design.md)**
   - Архитектура проекта
   - Технические решения
   - Структура данных

3. **Tasks (tasks.md)**
   - Список задач для реализации
   - Приоритеты и зависимости

## Преимущества

1. **Предотвращение ошибок** - невозможно создать план без необходимых данных
2. **Понятные сообщения** - пользователь видит какие именно поля нужно заполнить
3. **Проактивность** - кнопка скрывается если условия не выполнены
4. **Удобство** - автоматическое обновление после сохранения контекста
