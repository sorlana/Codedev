# План E2E тестирования: UI Integration for Agent Task Executor

## Обзор

Этот документ описывает план end-to-end тестирования интеграции UI с агентом выполнения задач. Тестирование охватывает все основные сценарии использования, обработку ошибок и граничные случаи.

## Цели тестирования

1. Проверить полный цикл выполнения задач через UI
2. Проверить корректность распознавания команд на русском и английском языках
3. Проверить работу кнопок управления и индикаторов прогресса
4. Проверить обработку ошибок и граничных случаев
5. Проверить переключение между диалогами с активным выполнением
6. Проверить автоматическое определение и указание путей к tasks.md

## Предварительные требования

### Подготовка окружения

1. **База данных:**
   - Создать чистую тестовую базу данных
   - Применить все миграции

2. **Тестовый проект:**
   - Создать тестовую директорию с C# проектом
   - Инициализировать Git репозиторий
   - Создать файлы tasks.md для различных сценариев

3. **Конфигурация:**
   - Настроить LLM провайдер (OpenAI или Ollama)
   - Настроить Serena MCP Server
   - Проверить доступность всех сервисов

### Тестовые данные

Создать следующие файлы tasks.md:

**tasks.md (корень проекта):**
```markdown
# Тестовые задачи

- [ ] 1. Простая задача
  - Создать файл test.txt с текстом "Hello World"
  
- [ ] 2. Задача с ошибкой
  - Создать файл в несуществующей директории
  
- [ ] 3. Финальная задача
  - Вывести сообщение "Все готово"
```

**.kiro/specs/feature/tasks.md:**
```markdown
# Задачи спецификации

- [ ] 1. Задача спецификации
  - Создать файл spec-test.txt
```

## Тестовые сценарии

### Сценарий 1: Полный цикл выполнения задач

**Цель:** Проверить полный цикл от запуска до завершения выполнения задач.

**Шаги:**

1. **Подготовка:**
   - Запустить приложение
   - Открыть веб-интерфейс (http://localhost:5000)
   - Создать новый диалог с именем "E2E Test - Full Cycle"
   - Указать путь к тестовому проекту

2. **Запуск выполнения:**
   - Ввести команду: "начни выполнение задач из tasks.md"
   - Нажать "Отправить"

3. **Проверки во время выполнения:**
   - ✅ Появилось подтверждающее сообщение о запуске
   - ✅ Отображается кнопка "Остановить"
   - ✅ Кнопка "Возобновить" скрыта
   - ✅ Отображается индикатор статуса с эмодзи 🔄
   - ✅ Индикатор показывает "Выполняется..."
   - ✅ Отображается прогресс "N/M задач"
   - ✅ Появляются сообщения о прогрессе:
     - 🤖 Начинаю выполнение задачи...
     - 📌 Создаю чекпоинт...
     - 🧠 Отправляю задачу в LLM...
     - ✅ Задача выполнена успешно
     - 📝 Обновляю статус задачи в файле
     - ⏱️ Время выполнения: ...
   - ✅ Чат автоматически прокручивается к последнему сообщению

4. **Проверки после завершения:**
   - ✅ Появилось финальное сообщение: "🎉 Все задачи выполнены успешно!"
   - ✅ Кнопки управления скрыты
   - ✅ Индикатор статуса показывает "✅ Завершено"
   - ✅ Polling остановлен (проверить в DevTools Network)
   - ✅ Файл tasks.md обновлен (задачи отмечены как выполненные)
   - ✅ Созданы Git чекпоинты

**Ожидаемый результат:** Все задачи выполнены успешно, UI корректно отображает прогресс и финальный статус.

### Сценарий 3: Обработка ошибок

**Цель:** Проверить корректную обработку различных ошибочных ситуаций.

#### 3.1. Файл tasks.md не найден в корне проекта

**Шаги:**
1. Создать новый диалог "E2E Test - File Not Found"
2. Удалить файл tasks.md из корня проекта
3. Ввести команду: "начни выполнение задач"

**Проверки:**
- ✅ Появилось сообщение: "❌ Файл tasks.md не найден в корне проекта. Укажите путь к файлу."
- ✅ Кнопки управления не отображаются
- ✅ Индикатор статуса не отображается

#### 3.2. Файл не найден по указанному пути

**Шаги:**
1. Ввести команду: "execute tasks from .kiro/specs/nonexistent/tasks.md"

**Проверки:**
- ✅ Появилось сообщение: "❌ Файл .kiro/specs/nonexistent/tasks.md не найден. Проверьте путь и попробуйте снова."
- ✅ Кнопки управления не отображаются

#### 3.3. Невалидный путь к файлу

**Шаги:**
1. Ввести команду: "начни выполнение задач из ../../etc/passwd"

**Проверки:**
- ✅ Появилось сообщение: "❌ Невалидный путь к файлу"
- ✅ Путь не прошел валидацию через PathValidator

#### 3.4. Попытка возобновить без остановленной сессии

**Шаги:**
1. Создать новый диалог без запущенного выполнения
2. Ввести команду: "продолжи выполнение"

**Проверки:**
- ✅ Появилось сообщение: "❌ Нет остановленной сессии для возобновления"
- ✅ Кнопки управления не отображаются

#### 3.5. Попытка запустить выполнение, когда оно уже запущено

**Шаги:**
1. Запустить выполнение задач
2. Пока выполнение активно, ввести команду: "начни выполнение задач"

**Проверки:**
- ✅ Появилось сообщение: "❌ Выполнение уже запущено"
- ✅ Текущее выполнение не прервано

**Ожидаемый результат:** Все ошибки обрабатываются корректно с понятными сообщениями.

### Сценарий 4: Переключение между диалогами с активным выполнением

**Цель:** Проверить корректность работы при переключении между диалогами.

**Шаги:**

1. **Подготовка:**
   - Создать диалог "Dialogue A" с tasks.md (5 задач)
   - Создать диалог "Dialogue B" с tasks.md (3 задачи)

2. **Запуск выполнения в Dialogue A:**
   - Выбрать "Dialogue A"
   - Ввести команду: "начни выполнение задач"
   - Дождаться начала выполнения

3. **Проверки в Dialogue A:**
   - ✅ Отображается кнопка "Остановить"
   - ✅ Индикатор статуса показывает "🔄 Выполняется..."
   - ✅ Polling активен (проверить в DevTools Network)

4. **Переключение на Dialogue B:**
   - Выбрать "Dialogue B" из списка диалогов

5. **Проверки в Dialogue B:**
   - ✅ Кнопки управления не отображаются (нет активного выполнения)
   - ✅ Индикатор статуса не отображается
   - ✅ Polling для Dialogue A остановлен
   - ✅ Polling для Dialogue B не запущен

6. **Возврат к Dialogue A:**
   - Выбрать "Dialogue A" из списка диалогов

7. **Проверки при возврате к Dialogue A:**
   - ✅ Кнопка "Остановить" отображается (если выполнение еще идет)
   - ✅ Индикатор статуса показывает актуальный статус
   - ✅ Polling возобновлен
   - ✅ Отображаются все сообщения о прогрессе, созданные во время отсутствия

8. **Запуск выполнения в Dialogue B:**
   - Находясь в Dialogue B, ввести команду: "start execution"
   - Проверить, что выполнение запускается независимо от Dialogue A

**Ожидаемый результат:** Каждый диалог имеет независимое состояние выполнения, polling корректно управляется при переключении.

```csharp
// Пример автоматизированного теста
[Fact]
public async Task E2E_FullCycle_ExecutesTasks()
{
    // Arrange
    var driver = new ChromeDriver();
    driver.Navigate().GoToUrl("http://localhost:5000");
    
    // Act
    var input = driver.FindElement(By.Id("prompt-input"));
    input.SendKeys("начни выполнение задач из tasks.md");
    
    var sendButton = driver.FindElement(By.Id("send-button"));
    sendButton.Click();
    
    // Assert
    var stopButton = driver.FindElement(By.Id("stop-execution-btn"));
    Assert.True(stopButton.Displayed);
    
    // Wait for completion
    await Task.Delay(60000);
    
    var indicator = driver.FindElement(By.Id("execution-status-indicator"));
    Assert.Contains("✅ Завершено", indicator.Text);
}
```
