## 3. Ручное тестирование функций

### 3.1 WebSocket соединение

#### Тест 3.1.1: Установка соединения
1. Откройте главную страницу приложения
2. Откройте консоль разработчика (F12)
3. Выберите существующий диалог или создайте новый
4. Проверьте в консоли сообщение о подключении WebSocket

**Ожидаемый результат:**
- [ ] В консоли появилось сообщение "[WebSocket] Соединение установлено"
- [ ] Индикатор статуса показывает "WebSocket" (зеленый)

#### Тест 3.1.2: Автоматическое переподключение
1. При активном WebSocket соединении
2. Остановите сервер (Ctrl+C)
3. Наблюдайте за попытками переподключения в консоли
4. Запустите сервер снова
5. Проверьте восстановление соединения

**Ожидаемый результат:**
- [ ] Система пытается переподключиться с экспоненциальной задержкой (1s, 2s, 4s, 8s)
- [ ] После восстановления сервера соединение восстанавливается
- [ ] Пропущенные сообщения синхронизируются

#### Тест 3.1.3: Fallback на HTTP
1. Остановите сервер
2. Дождитесь 5 неудачных попыток переподключения
3. Запустите сервер
4. Отправьте сообщение

**Ожидаемый результат:**
- [ ] После 5 попыток система переключается на HTTP режим
- [ ] Индикатор статуса показывает "HTTP" (желтый)
- [ ] Сообщения отправляются через HTTP API
- [ ] Появляется уведомление о переключении режима

### 3.2 Потоковая передача (Streaming)

#### Тест 3.2.1: Базовый streaming
1. Отправьте сообщение "Объясни принцип работы SOLID"
2. Наблюдайте за появлением ответа

**Ожидаемый результат:**
- [ ] Сразу создается пустое сообщение ассистента
- [ ] Текст появляется постепенно, фрагмент за фрагментом
- [ ] Визуально плавное добавление текста без задержек
- [ ] После завершения сообщение помечается как завершенное

#### Тест 3.2.2: Измерение TTFB
1. Откройте консоль разработчика
2. Отправьте сообщение
3. Проверьте логи TTFB в консоли

**Ожидаемый результат:**
- [ ] В консоли появляется сообщение с TTFB (Time To First Byte)
- [ ] TTFB < 2000ms для большинства запросов

#### Тест 3.2.3: Отмена генерации
1. Отправьте сообщение с длинным ответом
2. Во время генерации нажмите кнопку "Остановить генерацию"

**Ожидаемый результат:**
- [ ] Генерация останавливается в течение 1 секунды
- [ ] Частичный ответ сохраняется и отображается
- [ ] Кнопка "Остановить" исчезает

#### Тест 3.2.4: Обработка ошибок
1. Отправьте сообщение
2. Во время генерации остановите LLM сервис (если возможно)

**Ожидаемый результат:**
- [ ] Отображается частичный ответ (если был получен)
- [ ] Показывается сообщение об ошибке
- [ ] Предлагается повторить запрос

### 3.3 Кэширование сообщений

#### Тест 3.3.1: Сохранение в кэш
1. Отправьте несколько сообщений в диалоге
2. Откройте DevTools → Application → Local Storage
3. Проверьте наличие ключа `msg_cache_{dialogueId}`

**Ожидаемый результат:**
- [ ] Сообщения сохранены в localStorage
- [ ] Структура данных корректна (dialogueId, messages, lastUpdated)

#### Тест 3.3.2: Быстрая загрузка из кэша
1. Переключитесь на другой диалог
2. Вернитесь к предыдущему диалогу
3. Измерьте время отображения сообщений

**Ожидаемый результат:**
- [ ] Сообщения отображаются мгновенно (< 100ms)
- [ ] Затем происходит фоновая синхронизация с сервером

#### Тест 3.3.3: Ограничение размера кэша
1. Создайте диалог с >150 сообщениями
2. Проверьте localStorage

**Ожидаемый результат:**
- [ ] В кэше хранится не более 100 последних сообщений
- [ ] Старые сообщения автоматически удаляются

#### Тест 3.3.4: Очистка устаревшего кэша
1. Откройте DevTools → Application → Local Storage
2. Вручную измените timestamp старого кэша на 25 часов назад
3. Перезагрузите страницу

**Ожидаемый результат:**
- [ ] Устаревший кэш автоматически удаляется при инициализации

### 3.4 Виртуализация списка

#### Тест 3.4.1: Рендеринг только видимых элементов
1. Откройте диалог с >100 сообщениями
2. Откройте DevTools → Elements
3. Проверьте количество DOM элементов сообщений

**Ожидаемый результат:**
- [ ] В DOM присутствуют только видимые сообщения + буфер (~20-30 элементов)
- [ ] При прокрутке элементы динамически добавляются/удаляются

#### Тест 3.4.2: Производительность прокрутки
1. Откройте диалог с >500 сообщениями
2. Быстро прокрутите список вверх и вниз
3. Наблюдайте за плавностью

**Ожидаемый результат:**
- [ ] Прокрутка плавная, без лагов
- [ ] FPS >= 60 (проверить в Performance monitor)
- [ ] Нет визуальных артефактов

#### Тест 3.4.3: Подгрузка истории
1. Откройте диалог
2. Прокрутите к самому началу списка
3. Продолжайте прокручивать вверх

**Ожидаемый результат:**
- [ ] При достижении порога (20 сообщений от начала) загружаются предыдущие сообщения
- [ ] Позиция прокрутки сохраняется после загрузки
- [ ] Индикатор загрузки отображается

#### Тест 3.4.4: Поиск по сообщениям
1. Откройте диалог с большим количеством сообщений
2. Введите поисковый запрос в поле поиска
3. Нажмите Enter

**Ожидаемый результат:**
- [ ] Поиск работает по всем сообщениям (включая не отрендеренные)
- [ ] Список прокручивается к первому результату
- [ ] Найденное сообщение подсвечивается

#### Тест 3.4.5: Автопрокрутка к новым сообщениям
1. Прокрутите список к концу (последнее сообщение)
2. Отправьте новое сообщение
3. Повторите, но прокрутите список к середине

**Ожидаемый результат:**
- [ ] Если пользователь в конце списка - автоматическая прокрутка к новому сообщению
- [ ] Если пользователь читает старые сообщения - прокрутка не происходит

### 3.5 Автосохранение черновиков

#### Тест 3.5.1: Debouncing автосохранения
1. Начните вводить текст в поле ввода
2. Продолжайте вводить без остановки 5 секунд
3. Остановитесь и подождите 2 секунды
4. Проверьте localStorage

**Ожидаемый результат:**
- [ ] Черновик сохраняется только через 2 секунды после последнего нажатия клавиши
- [ ] Промежуточные сохранения не происходят

#### Тест 3.5.2: Переключение между диалогами
1. Введите текст в поле ввода диалога 1
2. Переключитесь на диалог 2
3. Введите другой текст
4. Вернитесь к диалогу 1

**Ожидаемый результат:**
- [ ] Черновик диалога 1 сохранен и восстановлен
- [ ] Черновик диалога 2 сохранен отдельно
- [ ] Каждый диалог имеет свой черновик

#### Тест 3.5.3: Восстановление после перезагрузки
1. Введите текст в поле ввода
2. Подождите 2 секунды (debounce)
3. Перезагрузите страницу (F5)
4. Откройте тот же диалог

**Ожидаемый результат:**
- [ ] Черновик восстановлен в поле ввода
- [ ] Текст полностью совпадает с введенным

#### Тест 3.5.4: Удаление после отправки
1. Введите текст в поле ввода
2. Отправьте сообщение
3. Проверьте localStorage

**Ожидаемый результат:**
- [ ] Черновик удален из localStorage после отправки
- [ ] Поле ввода очищено

#### Тест 3.5.5: Предотвращение пустых черновиков
1. Введите только пробелы в поле ввода
2. Подождите 2 секунды
3. Проверьте localStorage

**Ожидаемый результат:**
- [ ] Пустой черновик не сохраняется в localStorage

## Приложение B: Известные ограничения

1. **Streaming** требует поддержки WebSocket и Server-Sent Events
2. **Виртуализация** требует IntersectionObserver и ResizeObserver (IE11 не поддерживается)
3. **Кэширование** требует доступный localStorage (не работает в приватном режиме некоторых браузеров)
4. **Автосохранение черновиков** требует localStorage
5. **TTFB** зависит от скорости LLM сервиса и сетевого соединения
