## 🔄 В процессе

### Backend (осталось)

1. **API Endpoints в Program.cs:**
   - POST `/api/dialogues/{id}/plan-tasks` - создание плана
   - POST `/api/dialogues/{id}/execute-task` - выполнение задачи
   - POST `/api/dialogues/{id}/stop-task` - остановка задачи

2. **Доработка TaskPlannerService:**
   - Реализация ExecuteTaskAsync с реальным выполнением через Llama
   - Создание файлов и папок через Serena
   - Streaming прогресса через WebSocket

3. **DTO модели в RequestModels.cs:**
   - PlanTasksRequest
   - ExecuteTaskRequest
   - StopTaskRequest

### Frontend (осталось)

1. **HTML структура (index.html):**
   - Кнопка "Задачи" рядом с "Отправить"
   - Левая панель для плана задач
   - Аккордеон для задач и подзадач

2. **JavaScript функции (app.js):**
   - `showTasksButton()` - показать кнопку если Tasks заполнено
   - `openTaskPanel()` - открыть панель задач
   - `createTaskPlan()` - запрос плана у DeepSeek
   - `renderTaskPlan()` - отрисовка плана в левой панели
   - `executeTask()` - запуск одной задачи
   - `executeAllTasks()` - запуск всех задач
   - `stopTask()` - остановка задачи

3. **CSS стили (index.html):**
   - `.task-panel` - левая панель
   - `.task-accordion` - аккордеон
   - `.task-item` - элемент задачи
   - `.task-code` - блок кода
   - Анимации и переходы

## 💡 Технические решения

### Почему DeepSeek для планирования?
- Reasoning модель лучше анализирует контекст
- Создает более детальные планы
- Понимает архитектуру проекта

### Почему Llama для выполнения?
- Быстрее выполняет простые задачи
- Хорошо работает с инструментами (Serena)
- Меньше стоимость при большом объеме работы

### Почему WebSocket для прогресса?
- Real-time обновления
- Не блокирует UI
- Можно отменить выполнение

## 📝 Примечания
