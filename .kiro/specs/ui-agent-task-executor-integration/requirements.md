# Документ требований: UI Integration for Agent Task Executor

## Введение

UI Integration for Agent Task Executor - это функция для управления агентским режимом выполнения задач через веб-интерфейс чата. Система позволяет пользователям запускать, останавливать и отслеживать выполнение задач из файла tasks.md через естественные команды в диалоге, без необходимости запоминать ID или использовать API напрямую. Интерфейс предоставляет детальную отчетность о каждом шаге выполнения, визуальные индикаторы прогресса и кнопки управления, создавая опыт, похожий на работу с Kiro в режиме autopilot.

## Глоссарий

- **Chat_Interface**: Веб-интерфейс чата для взаимодействия с пользователем
- **Command_Recognizer**: Компонент для распознавания команд управления агентским режимом
- **Progress_Reporter**: Компонент для отображения прогресса выполнения в чате
- **Control_Buttons**: Кнопки управления выполнением (Остановить, Возобновить)
- **Status_Indicator**: Визуальный индикатор текущего статуса выполнения
- **PromptProcessor**: Существующий сервис для обработки промптов
- **TaskExecutorService**: Существующий сервис для выполнения задач из tasks.md
- **Active_Dialogue**: Текущий открытый диалог в интерфейсе чата
- **Execution_Status**: Статус выполнения (running, paused, stopped, completed, failed, none)
- **Task_Progress**: Прогресс выполнения в формате "N/M задач"

## Требования

### Требование 1: Распознавание команд управления в чате

**User Story:** Как пользователь, я хочу управлять агентским режимом через естественные команды в чате, чтобы не запоминать ID диалогов и не использовать API напрямую.

#### Критерии приемки

1. WHEN пользователь отправляет сообщение "начни выполнение задач из файла tasks.md", THEN THE Command_Recognizer SHALL распознать команду запуска выполнения
2. WHEN пользователь отправляет сообщение "execute tasks from tasks.md", THEN THE Command_Recognizer SHALL распознать команду запуска выполнения
3. WHEN пользователь отправляет сообщение "останови выполнение", THEN THE Command_Recognizer SHALL распознать команду остановки
4. WHEN пользователь отправляет сообщение "stop execution", THEN THE Command_Recognizer SHALL распознать команду остановки
5. WHEN пользователь отправляет сообщение "продолжи выполнение", THEN THE Command_Recognizer SHALL распознать команду возобновления
6. WHEN пользователь отправляет сообщение "resume execution", THEN THE Command_Recognizer SHALL распознать команду возобновления
7. WHEN пользователь отправляет сообщение "покажи статус выполнения", THEN THE Command_Recognizer SHALL распознать команду запроса статуса
8. WHEN пользователь отправляет сообщение "show execution status", THEN THE Command_Recognizer SHALL распознать команду запроса статуса
9. WHEN Command_Recognizer распознает команду, THEN THE System SHALL использовать ID текущего Active_Dialogue для выполнения команды
10. WHEN Command_Recognizer распознает команду запуска, THEN THE System SHALL извлечь путь к файлу tasks.md из текста команды

### Требование 2: Автоматическое определение пути к tasks.md

**User Story:** Как пользователь, я хочу, чтобы система автоматически находила файл tasks.md, чтобы не указывать полный путь каждый раз.

#### Критерии приемки

1. WHEN пользователь отправляет команду "начни выполнение задач" без указания пути, THEN THE System SHALL искать файл tasks.md в корне проекта текущего диалога
2. WHEN пользователь отправляет команду "начни выполнение задач из tasks.md", THEN THE System SHALL искать файл tasks.md в корне проекта
3. WHEN пользователь отправляет команду "начни выполнение задач из .kiro/specs/feature/tasks.md", THEN THE System SHALL использовать указанный относительный путь от корня проекта
4. WHEN System не находит файл tasks.md в корне проекта, THEN THE System SHALL отправить сообщение "Файл tasks.md не найден в корне проекта. Укажите путь к файлу."
5. WHEN System не находит файл по указанному пути, THEN THE System SHALL отправить сообщение "Файл [путь] не найден. Проверьте путь и попробуйте снова."
6. WHEN пользователь указывает путь к файлу, THEN THE System SHALL поддерживать относительные пути от корня проекта
7. WHEN пользователь указывает путь к файлу, THEN THE System SHALL валидировать путь через PathValidator

### Требование 3: Интеграция с PromptProcessor

**User Story:** Как разработчик, я хочу интегрировать команды управления в существующий PromptProcessor, чтобы использовать единую точку обработки всех пользовательских сообщений.

#### Критерии приемки

1. WHEN PromptProcessor получает сообщение от пользователя, THEN THE PromptProcessor SHALL проверить, является ли сообщение командой управления агентским режимом
2. WHEN PromptProcessor распознает команду запуска выполнения, THEN THE PromptProcessor SHALL вызвать TaskExecutorService.ExecuteTasksAsync
3. WHEN PromptProcessor распознает команду остановки, THEN THE PromptProcessor SHALL вызвать TaskExecutorService.StopExecutionAsync
4. WHEN PromptProcessor распознает команду возобновления, THEN THE PromptProcessor SHALL вызвать TaskExecutorService.ResumeExecutionAsync
5. WHEN PromptProcessor распознает команду запроса статуса, THEN THE PromptProcessor SHALL вызвать TaskExecutorService.GetExecutionStatusAsync
6. WHEN PromptProcessor обрабатывает команду управления, THEN THE PromptProcessor SHALL НЕ отправлять команду в LLM
7. WHEN PromptProcessor успешно выполняет команду, THEN THE PromptProcessor SHALL вернуть подтверждающее сообщение пользователю
8. WHEN PromptProcessor не может выполнить команду, THEN THE PromptProcessor SHALL вернуть сообщение об ошибке с объяснением причины

### Требование 4: Детальная отчетность в диалоге

**User Story:** Как пользователь, я хочу видеть детальную информацию о каждом шаге выполнения задач, чтобы понимать, что происходит в системе.

#### Критерии приемки

1. WHEN система начинает выполнение задачи, THEN THE Progress_Reporter SHALL отправить сообщение "🤖 Начинаю выполнение задачи N из M: [текст задачи]"
2. WHEN система создает Git чекпоинт, THEN THE Progress_Reporter SHALL отправить сообщение "📌 Создаю чекпоинт: [описание]"
3. WHEN система отправляет задачу в LLM, THEN THE Progress_Reporter SHALL отправить сообщение "🧠 Отправляю задачу в LLM..."
4. WHEN система получает ответ от LLM, THEN THE Progress_Reporter SHALL отправить сообщение "✅ Задача выполнена успешно"
5. WHEN система обновляет файл tasks.md, THEN THE Progress_Reporter SHALL отправить сообщение "📝 Обновляю статус задачи в файле"
6. WHEN система завершает выполнение задачи, THEN THE Progress_Reporter SHALL отправить сообщение с временем выполнения "⏱️ Время выполнения: [время]"
7. WHEN система встречает ошибку, THEN THE Progress_Reporter SHALL отправить сообщение "❌ Ошибка: [описание ошибки]"
8. WHEN система встречает ошибку, THEN THE Progress_Reporter SHALL отправить сообщение "🤔 Возможные причины: [рассуждения]"
9. WHEN система завершает все задачи, THEN THE Progress_Reporter SHALL отправить сообщение "🎉 Все задачи выполнены успешно! Выполнено N из M задач за [общее время]"
10. WHEN система останавливает выполнение, THEN THE Progress_Reporter SHALL отправить сообщение "⏸️ Выполнение остановлено. Выполнено N из M задач"
11. WHEN система возобновляет выполнение, THEN THE Progress_Reporter SHALL отправить сообщение "▶️ Продолжаю выполнение задач..."

### Требование 5: Кнопки управления выполнением

**User Story:** Как пользователь, я хочу видеть кнопки управления выполнением в интерфейсе чата, чтобы легко останавливать и возобновлять процесс.

#### Критерии приемки

1. WHEN система начинает выполнение задач, THEN THE Chat_Interface SHALL отобразить кнопку "Остановить" (Stop)
2. WHEN система начинает выполнение задач, THEN THE Chat_Interface SHALL скрыть кнопку "Возобновить" (Resume)
3. WHEN пользователь нажимает кнопку "Остановить", THEN THE Chat_Interface SHALL отправить команду остановки через API
4. WHEN система останавливает выполнение, THEN THE Chat_Interface SHALL скрыть кнопку "Остановить"
5. WHEN система останавливает выполнение, THEN THE Chat_Interface SHALL отобразить кнопку "Возобновить"
6. WHEN пользователь нажимает кнопку "Возобновить", THEN THE Chat_Interface SHALL отправить команду возобновления через API
7. WHEN система завершает все задачи, THEN THE Chat_Interface SHALL скрыть обе кнопки управления
8. WHEN система встречает ошибку, THEN THE Chat_Interface SHALL скрыть кнопку "Остановить" и отобразить кнопку "Возобновить"
9. WHEN кнопки управления отображаются, THEN THE Chat_Interface SHALL позиционировать их в видимой области интерфейса чата
10. WHEN пользователь взаимодействует с кнопками, THEN THE Chat_Interface SHALL предоставить визуальную обратную связь (loading state)

### Требование 6: Визуальная индикация прогресса

**User Story:** Как пользователь, я хочу видеть визуальные индикаторы прогресса выполнения, чтобы быстро оценивать текущее состояние процесса.

#### Критерии приемки

1. WHEN система выполняет задачи, THEN THE Status_Indicator SHALL отображать текущий прогресс в формате "N/M задач"
2. WHEN система выполняет задачи, THEN THE Status_Indicator SHALL отображать текущий статус "🔄 Выполняется..."
3. WHEN система останавливает выполнение, THEN THE Status_Indicator SHALL отображать статус "⏸️ Приостановлено"
4. WHEN система завершает все задачи, THEN THE Status_Indicator SHALL отображать статус "✅ Завершено"
5. WHEN система встречает ошибку, THEN THE Status_Indicator SHALL отображать статус "❌ Ошибка"
6. WHEN система не выполняет задачи, THEN THE Status_Indicator SHALL скрывать индикатор прогресса
7. WHEN система обновляет прогресс, THEN THE Status_Indicator SHALL использовать эмодзи для улучшения читаемости
8. WHEN система отображает сообщения о прогрессе, THEN THE Chat_Interface SHALL использовать форматирование Markdown для структурирования информации
9. WHEN система отображает текущую задачу, THEN THE Status_Indicator SHALL показывать краткое описание задачи (первые 50 символов)

### Требование 7: Обновление UI в реальном времени

**User Story:** Как пользователь, я хочу видеть обновления прогресса в реальном времени, чтобы не обновлять страницу вручную.

#### Критерии приемки

1. WHEN система выполняет задачи, THEN THE Chat_Interface SHALL периодически опрашивать статус выполнения через GET /api/dialogues/{id}/execution-status
2. WHEN Chat_Interface получает обновленный статус, THEN THE Chat_Interface SHALL обновить отображение прогресса без перезагрузки страницы
3. WHEN Chat_Interface получает обновленный статус, THEN THE Chat_Interface SHALL обновить состояние кнопок управления
4. WHEN Chat_Interface получает новые сообщения о прогрессе, THEN THE Chat_Interface SHALL автоматически прокручивать чат к последнему сообщению
5. WHEN система выполняет задачи, THEN THE Chat_Interface SHALL опрашивать статус каждые 2 секунды
6. WHEN система не выполняет задачи (status="none" или "completed"), THEN THE Chat_Interface SHALL прекратить опрос статуса
7. WHEN Chat_Interface опрашивает статус, THEN THE Chat_Interface SHALL обрабатывать ошибки сети без прерывания работы интерфейса
8. WHEN пользователь переключается на другой диалог, THEN THE Chat_Interface SHALL прекратить опрос статуса предыдущего диалога
9. WHEN пользователь возвращается к диалогу с активным выполнением, THEN THE Chat_Interface SHALL возобновить опрос статуса

### Требование 8: Отображение новых сообщений о прогрессе

**User Story:** Как пользователь, я хочу видеть новые сообщения о прогрессе по мере их появления, чтобы следить за выполнением в реальном времени.

#### Критерии приемки

1. WHEN система сохраняет новое сообщение о прогрессе в базу данных, THEN THE Chat_Interface SHALL получить это сообщение при следующем опросе
2. WHEN Chat_Interface получает новые сообщения, THEN THE Chat_Interface SHALL отобразить их в хронологическом порядке
3. WHEN Chat_Interface отображает сообщения о прогрессе, THEN THE Chat_Interface SHALL использовать role="assistant" для стилизации
4. WHEN Chat_Interface отображает сообщения с эмодзи, THEN THE Chat_Interface SHALL корректно рендерить Unicode символы
5. WHEN Chat_Interface отображает сообщения с Markdown, THEN THE Chat_Interface SHALL корректно рендерить форматирование
6. WHEN Chat_Interface получает сообщение об ошибке, THEN THE Chat_Interface SHALL выделить его визуально (красный цвет или специальный стиль)
7. WHEN Chat_Interface получает итоговое сообщение о завершении, THEN THE Chat_Interface SHALL выделить его визуально (зеленый цвет или специальный стиль)

### Требование 9: Обработка ошибок в UI

**User Story:** Как пользователь, я хочу видеть понятные сообщения об ошибках, чтобы понимать, что пошло не так и как это исправить.

#### Критерии приемки

1. WHEN API возвращает ошибку 404 (диалог не найден), THEN THE Chat_Interface SHALL отобразить сообщение "Диалог не найден"
2. WHEN API возвращает ошибку 400 (файл не найден), THEN THE Chat_Interface SHALL отобразить сообщение "Файл tasks.md не найден. Проверьте путь."
3. WHEN API возвращает ошибку 400 (невалидный путь), THEN THE Chat_Interface SHALL отобразить сообщение "Невалидный путь к файлу"
4. WHEN API возвращает ошибку 500, THEN THE Chat_Interface SHALL отобразить сообщение "Внутренняя ошибка сервера. Попробуйте позже."
5. WHEN происходит ошибка сети, THEN THE Chat_Interface SHALL отобразить сообщение "Ошибка соединения. Проверьте подключение к интернету."
6. WHEN пользователь пытается запустить выполнение, когда оно уже запущено, THEN THE Chat_Interface SHALL отобразить сообщение "Выполнение уже запущено"
7. WHEN пользователь пытается возобновить выполнение, когда нет остановленной сессии, THEN THE Chat_Interface SHALL отобразить сообщение "Нет остановленной сессии для возобновления"
8. WHEN Chat_Interface отображает сообщение об ошибке, THEN THE Chat_Interface SHALL использовать эмодзи ❌ для визуального выделения

### Требование 10: Интеграция с существующим frontend

**User Story:** Как разработчик, я хочу интегрировать новую функциональность в существующий frontend, чтобы использовать имеющуюся инфраструктуру.

#### Критерии приемки

1. THE Chat_Interface SHALL использовать существующую функцию sendMessage() для отправки команд
2. THE Chat_Interface SHALL использовать существующую функцию loadMessages() для загрузки сообщений о прогрессе
3. THE Chat_Interface SHALL использовать существующую функцию displayMessage() для отображения сообщений
4. THE Chat_Interface SHALL добавить новую функцию pollExecutionStatus() для опроса статуса
5. THE Chat_Interface SHALL добавить новую функцию updateControlButtons() для обновления кнопок управления
6. THE Chat_Interface SHALL добавить новую функцию updateStatusIndicator() для обновления индикатора прогресса
7. THE Chat_Interface SHALL добавить HTML элементы для кнопок управления в существующий layout
8. THE Chat_Interface SHALL добавить HTML элементы для индикатора статуса в существующий layout
9. THE Chat_Interface SHALL использовать существующие CSS стили для единообразия интерфейса
10. THE Chat_Interface SHALL добавить новые CSS стили для кнопок управления и индикатора статуса

### Требование 11: Поддержка многоязычности команд

**User Story:** Как пользователь, я хочу использовать команды на русском или английском языке, чтобы работать в удобном для меня языке.

#### Критерии приемки

1. WHEN Command_Recognizer распознает команды, THEN THE Command_Recognizer SHALL поддерживать русские варианты команд
2. WHEN Command_Recognizer распознает команды, THEN THE Command_Recognizer SHALL поддерживать английские варианты команд
3. WHEN Command_Recognizer распознает команды, THEN THE Command_Recognizer SHALL игнорировать регистр символов
4. WHEN Command_Recognizer распознает команды, THEN THE Command_Recognizer SHALL поддерживать вариации команд (например, "начни выполнение", "запусти выполнение", "start execution", "execute tasks")
5. WHEN система отправляет сообщения пользователю, THEN THE System SHALL использовать язык, соответствующий языку команды пользователя
6. WHEN система не может определить язык команды, THEN THE System SHALL использовать русский язык по умолчанию

### Требование 12: Сохранение контекста диалога

**User Story:** Как пользователь, я хочу, чтобы система запоминала контекст выполнения в рамках диалога, чтобы не повторять информацию при каждой команде.

#### Критерии приемки

1. WHEN пользователь запускает выполнение задач в диалоге, THEN THE System SHALL сохранить путь к файлу tasks.md в контексте диалога
2. WHEN пользователь отправляет команду "продолжи выполнение" без указания файла, THEN THE System SHALL использовать путь из последней сессии выполнения
3. WHEN пользователь отправляет команду "покажи статус", THEN THE System SHALL использовать ID текущего диалога автоматически
4. WHEN пользователь переключается на другой диалог, THEN THE System SHALL использовать контекст нового диалога
5. WHEN пользователь закрывает и открывает диалог, THEN THE System SHALL восстановить контекст выполнения из базы данных

### Требование 13: Визуальное оформление сообщений о прогрессе

**User Story:** Как пользователь, я хочу видеть красиво оформленные сообщения о прогрессе, чтобы легко воспринимать информацию.

#### Критерии приемки

1. WHEN система отправляет сообщение о начале задачи, THEN THE System SHALL использовать эмодзи 🤖 в начале сообщения
2. WHEN система отправляет сообщение о создании чекпоинта, THEN THE System SHALL использовать эмодзи 📌
3. WHEN система отправляет сообщение об отправке в LLM, THEN THE System SHALL использовать эмодзи 🧠
4. WHEN система отправляет сообщение об успешном выполнении, THEN THE System SHALL использовать эмодзи ✅
5. WHEN система отправляет сообщение об обновлении файла, THEN THE System SHALL использовать эмодзи 📝
6. WHEN система отправляет сообщение о времени выполнения, THEN THE System SHALL использовать эмодзи ⏱️
7. WHEN система отправляет сообщение об ошибке, THEN THE System SHALL использовать эмодзи ❌
8. WHEN система отправляет сообщение о завершении всех задач, THEN THE System SHALL использовать эмодзи 🎉
9. WHEN система отправляет сообщение с несколькими пунктами, THEN THE System SHALL использовать Markdown списки для структурирования
10. WHEN система отправляет сообщение с кодом или путями, THEN THE System SHALL использовать Markdown code blocks для выделения
