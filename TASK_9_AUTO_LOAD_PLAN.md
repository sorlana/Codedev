# Автоматическая загрузка плана задач при выборе диалога

## Задача
При выборе диалога из группы автоматически показывать панель задач с сгенерированным планом, если он существует в БД для этой группы.

## Реализация

### 1. Добавлена функция автоматической загрузки
**Файл**: `wwwroot/app.js`

Создана функция `loadTaskPlanIfExists()`:
```javascript
async function loadTaskPlanIfExists() {
    // Проверяет наличие плана для текущего диалога
    // Если план существует - загружает и показывает панель задач
    // Если плана нет - скрывает панель задач
}
```

### 2. Интеграция в selectDialogue
Функция `selectDialogue()` теперь вызывает `loadTaskPlanIfExists()` после загрузки сообщений и чекпоинтов:
```javascript
async function selectDialogue(dialogueId) {
    // ... загрузка сообщений, чекпоинтов, WebSocket ...
    
    // Проверка и отображение кнопки "Задачи"
    checkAndShowTasksButton();
    
    // Автоматическая загрузка плана задач если он существует
    await loadTaskPlanIfExists();
}
```

### 3. Обновлена логика закрытия панели
Функция `closeTaskPanel()` больше не очищает `currentTaskPlan`:
```javascript
function closeTaskPanel() {
    // Скрывает панель, но план остается в памяти
    app.classList.remove('with-task-panel');
    taskPanel.style.display = 'none';
    
    // НЕ очищаем currentTaskPlan
    runningTasks.clear();
}
```

## Поведение

### Сценарий 1: Диалог с планом
1. Пользователь выбирает диалог из группы
2. Система проверяет наличие плана через API: `GET /api/dialogues/{id}/task-plan`
3. Если план существует (200 OK):
   - План загружается в `currentTaskPlan`
   - Панель задач автоматически открывается
   - План отображается с деревом папок и списком задач
   - Кнопка "Задачи" становится disabled

### Сценарий 2: Диалог без плана
1. Пользователь выбирает диалог
2. Система проверяет наличие плана
3. Если плана нет (404 Not Found):
   - Панель задач скрывается (если была открыта)
   - `currentTaskPlan` очищается
   - Кнопка "Задачи" активна (если есть Tasks в группе)

### Сценарий 3: Переключение между диалогами
1. Пользователь переключается с диалога A (с планом) на диалог B (без плана)
2. Панель задач автоматически скрывается
3. При возврате на диалог A панель снова открывается с планом

### Сценарий 4: Создание нового плана
1. Пользователь нажимает кнопку "Задачи"
2. Функция `openTaskPanel()` проверяет существующий план
3. Если план уже есть - загружает его
4. Если плана нет - создает новый через API
5. После создания кнопка "Задачи" становится disabled

## API Endpoints

### GET /api/dialogues/{id}/task-plan
Получение плана задач для диалога.

Ответы:
- 200 OK - план существует, возвращает JSON с планом
- 404 Not Found - план не существует
- 500 Internal Server Error - ошибка сервера

### POST /api/dialogues/{id}/plan-tasks
Создание нового плана задач.

Ответы:
- 200 OK - план создан успешно
- 400 Bad Request - ошибка валидации
- 500 Internal Server Error - ошибка создания

## Преимущества

1. **Автоматизация** - пользователю не нужно вручную открывать панель задач
2. **Контекстность** - план всегда соответствует выбранному диалогу
3. **Персистентность** - план сохраняется в БД и доступен при повторном открытии
4. **Удобство** - панель автоматически скрывается для диалогов без плана
