# Checkpoint: Тестирование WebSocket и streaming

## Цель
Проверить работоспособность WebSocket соединения и потоковой передачи ответов LLM.

## Предварительные требования
1. Приложение должно быть запущено: `dotnet run`
2. Браузер открыт на http://localhost:5000
3. DevTools открыты (F12)

## Тесты

### ТЕСТ 1: WebSocket соединение устанавливается при загрузке

**Шаги:**
1. Откройте DevTools (F12) и перейдите на вкладку Console
2. Создайте или выберите существующий диалог
3. Проверьте в консоли сообщения:
   - `[WebSocket] Подключение к ws://localhost:5000/ws?dialogueId=X...`
   - `[WebSocket] Соединение установлено`
4. Перейдите на вкладку Network → WS (WebSocket)
5. Убедитесь, что есть активное WebSocket соединение

**Ожидаемый результат:**
- ✅ WebSocket соединение установлено
- ✅ В консоли видны логи подключения
- ✅ На вкладке Network → WS видно активное соединение

**Статус:** [ ] Пройден / [ ] Не пройден

---

### ТЕСТ 2: Отправка сообщений через WebSocket

**Шаги:**
1. В поле ввода введите простое сообщение: "Привет"
2. Нажмите "Отправить" или Enter
3. В консоли проверьте сообщения:
   - `[UI] Отправка сообщения через WebSocket`
   - `[WebSocket] Сообщение отправлено: {type: user_message, ...}`
4. На вкладке Network → WS проверьте отправленное сообщение
5. Убедитесь, что сообщение пользователя отображается мгновенно

**Ожидаемый результат:**
- ✅ Сообщение отправлено через WebSocket
- ✅ Сообщение пользователя отображается мгновенно
- ✅ В консоли видны логи отправки

**Статус:** [ ] Пройден / [ ] Не пройден

---

### ТЕСТ 3: Отображение streaming ответа по частям

**Шаги:**
1. Отправьте сообщение, которое вызовет ответ LLM:
   - Например: "Объясни что такое рефакторинг"
2. Наблюдайте за консолью:
   - `[UI] Получено assistant_message_start`
   - `[UI] Получен assistant_message_chunk` (несколько раз)
   - `[UI] Получено assistant_message_end`
3. Убедитесь, что ответ появляется постепенно, по частям
4. Проверьте, что текст добавляется плавно без мерцания
5. Проверьте логи времени рендеринга в консоли

**Ожидаемый результат:**
- ✅ Ответ отображается постепенно, по частям
- ✅ Текст добавляется плавно
- ✅ В консоли видны логи streaming событий
- ✅ Время рендеринга фрагментов < 50ms

**Статус:** [ ] Пройден / [ ] Не пройден

### ТЕСТ 4: Работа кнопки "Остановить генерацию"

**Шаги:**
1. Отправьте сообщение, которое вызовет длинный ответ:
   - Например: "Расскажи подробно о паттернах проектирования"
2. Как только начнется streaming, нажмите кнопку "⏹ Остановить генерацию"
3. Проверьте в консоли:
   - `[UI] Отправка команды отмены генерации`
   - `[UI] Команда отмены отправлена успешно`
4. Убедитесь, что генерация остановилась в течение 1 секунды
5. Убедитесь, что кнопка "Остановить генерацию" исчезла
6. Проверьте, что частичный ответ сохранен и отображается

**Ожидаемый результат:**
- ✅ Кнопка "Остановить генерацию" появляется при streaming
- ✅ Генерация останавливается в течение 1 секунды
- ✅ Кнопка исчезает после остановки
- ✅ Частичный ответ сохранен и отображается

**Статус:** [ ] Пройден / [ ] Не пройден

### ТЕСТ 5: Автоматическое переподключение при разрыве

**Шаги:**
1. В консоли DevTools выполните команду для закрытия WebSocket:
   ```javascript
   wsClient.ws.close()
   ```
2. Наблюдайте за консолью:
   - `[WebSocket] Соединение закрыто`
   - `[WebSocket] Попытка переподключения 1/5 через Xms...`
   - `[WebSocket] Подключение к ws://...`
   - `[WebSocket] Соединение установлено`
3. Убедитесь, что переподключение произошло автоматически
4. Проверьте, что задержка увеличивается экспоненциально:
   - Попытка 1: ~1000ms
   - Попытка 2: ~2000ms
   - Попытка 3: ~4000ms
5. Отправьте тестовое сообщение после переподключения
6. Убедитесь, что сообщение отправляется успешно

**Ожидаемый результат:**
- ✅ Переподключение происходит автоматически
- ✅ Задержка увеличивается экспоненциально
- ✅ После переподключения сообщения отправляются успешно
- ✅ Максимальная задержка не превышает 30 секунд

**Статус:** [ ] Пройден / [ ] Не пройден
