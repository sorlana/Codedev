# Тестирование WebSocket Streaming

## Проблема
При общении с моделью в чате раньше было видно, как ассистент "печатает", затем в чат появлялся ответ. Сейчас чтобы увидеть ответ, нужно перезагружать страницу.

## Исправления
1. Улучшена обработка WebSocket сообщений на клиенте
2. Добавлено автоматическое создание streaming сообщения при получении первого фрагмента
3. Добавлено подробное логирование для отладки
4. Исправлено измерение TTFB (Time To First Byte)

## Как протестировать

### Вариант 1: Основное приложение
1. Запустите приложение:
   ```bash
   dotnet run
   ```

2. Откройте браузер: http://localhost:5000

3. Откройте консоль разработчика (F12)

4. Создайте или выберите диалог

5. Отправьте сообщение и наблюдайте:
   - В консоли должны появиться логи WebSocket
   - Сообщение должно появляться по мере генерации (streaming)
   - Индикатор "печатает..." должен исчезнуть при получении первого фрагмента

### Вариант 2: Тестовая страница
1. Запустите приложение:
   ```bash
   dotnet run
   ```

2. Откройте тестовую страницу: http://localhost:5000/test-websocket-streaming.html

3. Нажмите "Подключиться"

4. Введите сообщение и нажмите "Отправить"

5. Наблюдайте:
   - Лог событий показывает все WebSocket сообщения
   - Полученное сообщение отображается в реальном времени
   - Статус подключения обновляется

## Возможные проблемы

### WebSocket не подключается
- Проверьте, что приложение запущено
- Проверьте URL в консоли браузера
- Убедитесь, что диалог существует

### Сообщения не отображаются
- Откройте консоль браузера (F12)
- Проверьте, приходят ли WebSocket сообщения
- Проверьте, зарегистрированы ли обработчики
- Посмотрите логи сервера

### Индикатор "печатает..." не исчезает
- Проверьте, что приходит `assistant_message_start` или `assistant_message_chunk`
- Убедитесь, что обработчики правильно удаляют индикатор
- Проверьте ID элемента `typing-indicator`
