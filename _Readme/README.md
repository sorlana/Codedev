# C# Refactoring Assistant

AI-ассистент для рефакторинга C# кода через Serena MCP + Git. Веб-приложение на ASP.NET Core с интерфейсом чата для выполнения семантического рефакторинга C# проектов с помощью естественного языка.

## Возможности

- 🤖 Интерпретация команд рефакторинга на естественном языке через LLM (OpenAI/DeepSeek)
- 🔍 Семантический анализ и редактирование C# кода через Serena MCP Server
- 💾 Автоматическое создание Git чекпоинтов перед каждым изменением
- ⏮️ Откат к любому предыдущему состоянию проекта
- 💬 Ведение истории диалогов для разных проектов
- 🌐 Веб-интерфейс для удобного взаимодействия
- 🚀 **Агентский режим** - автоматическое выполнение задач из файла tasks.md

## Требования к системе

- .NET 10 SDK
- Git
- Docker (для запуска Serena MCP Server)
- OpenAI API ключ (DeepSeek или другой совместимый провайдер)

## Установка и настройка

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd CSharpRefactoringAssistant
```

### 2. Настройка конфигурации

Отредактируйте файл `appsettings.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=refactoring.db"
  },
  "Llm": {
    "Provider": "OpenAI",
    "OpenAI": {
      "ApiKey": "ваш-api-ключ",
      "Model": "deepseek-chat",
      "BaseUrl": "https://api.deepseek.com/v1"
    }
  },
  "Serena": {
    "StdioCommand": "docker",
    "StdioArgs": ["exec", "-i", "serena-container", "serena-mcp"]
  },
  "Security": {
    "AllowedRootDirectory": null
  }
}
```

**Важно:** Замените `"ваш-api-ключ"` на реальный API ключ от DeepSeek или OpenAI.

### 3. Запуск Serena MCP Server в Docker

```bash
# Создайте и запустите контейнер Serena
docker run -d --name serena-container serena-mcp-image

# Проверьте, что контейнер запущен
docker ps | grep serena-container
```

**Примечание:** Замените `serena-mcp-image` на актуальное имя образа Serena MCP Server.

### 4. Восстановление зависимостей

```bash
dotnet restore
```

### 5. Запуск приложения

```bash
dotnet run
```

Приложение будет доступно по адресу: `http://localhost:5000` (или другой порт, указанный в консоли).

## Использование

### Создание нового диалога

1. Откройте веб-интерфейс в браузере
2. В левой панели введите абсолютный путь к вашему C# проекту
3. Нажмите "Создать диалог"
4. Если проект не является Git репозиторием, он будет автоматически инициализирован

### Выполнение рефакторинга

Введите команду на естественном языке в поле ввода, например:

```
Найди все места, где используется атрибут [Authorize], и замени его на [CustomAuthorize] с проверкой роли Admin
```

```
Переименуй метод GetUserData в GetUserInformation во всех файлах проекта
```

```
Добавь логирование в начало каждого публичного метода в классе UserService
```

### Откат изменений

1. В правой панели отображаются все чекпоинты (Git коммиты)
2. Нажмите кнопку "Откатить" рядом с нужным чекпоинтом
3. Проект будет восстановлен до этого состояния

## Агентский режим выполнения задач

Агентский режим позволяет автоматически выполнять последовательность задач из файла `tasks.md` через веб-интерфейс чата или API. Система последовательно обрабатывает незавершенные задачи, создает Git чекпоинты перед каждой задачей и отслеживает прогресс выполнения в реальном времени.

### Управление через веб-интерфейс

Вы можете управлять выполнением задач прямо из чата, используя естественные команды на русском или английском языке.

#### Команды управления

**Запуск выполнения:**
- `начни выполнение задач из tasks.md` - запустить выполнение из корня проекта
- `начни выполнение задач из .kiro/specs/feature/tasks.md` - запустить с указанием пути
- `execute tasks from tasks.md` - английский вариант
- `start execution` - краткий вариант

**Остановка выполнения:**
- `останови выполнение` - остановить текущее выполнение
- `stop execution` - английский вариант
- `стоп` - краткий вариант

**Возобновление выполнения:**
- `продолжи выполнение` - продолжить с места остановки
- `resume execution` - английский вариант
- `возобнови выполнение` - альтернативный вариант

**Проверка статуса:**
- `покажи статус выполнения` - показать текущий статус
- `show execution status` - английский вариант
- `статус` - краткий вариант

#### Визуальные элементы управления

**Индикатор прогресса:**
Во время выполнения задач в интерфейсе отображается индикатор с информацией:
- 🔄 Выполняется... (3/10 задач) - текущий прогресс
- ⏸️ Приостановлено (3/10 задач) - выполнение остановлено
- ✅ Завершено (10/10 задач) - все задачи выполнены
- ❌ Ошибка - произошла ошибка при выполнении

**Кнопки управления:**
- **Остановить** (красная кнопка) - появляется во время выполнения
- **Возобновить** (зеленая кнопка) - появляется после остановки

**Сообщения о прогрессе:**
Система отправляет детальные сообщения о каждом шаге:
- 🤖 Начинаю выполнение задачи N из M: [текст задачи]
- 📌 Создаю чекпоинт: [описание]
- 🧠 Отправляю задачу в LLM...
- ✅ Задача выполнена за X.Xс
- 📝 Обновляю статус задачи в файле
- ⏱️ Время выполнения: X.Xс
- ❌ Ошибка: [описание ошибки]
- 🎉 Все задачи выполнены успешно!

#### Примеры использования

**Пример 1: Запуск выполнения из корня проекта**
```
Пользователь: начни выполнение задач из tasks.md
Система: ✅ Запускаю выполнение задач из файла tasks.md
Система: 🤖 Начинаю выполнение задачи 1 из 5: Создать класс UserService
[Кнопка "Остановить" появляется]
[Индикатор показывает: 🔄 Выполняется... (1/5 задач)]
```

**Пример 2: Остановка и возобновление**
```
Пользователь: [нажимает кнопку "Остановить"]
Система: ⏸️ Выполнение остановлено. Выполнено 2 из 5 задач
[Кнопка "Возобновить" появляется]
[Индикатор показывает: ⏸️ Приостановлено (2/5 задач)]

Пользователь: продолжи выполнение
Система: ▶️ Продолжаю выполнение задач...

```

**Пример 3: Запуск с указанием пути**
```
Пользователь: начни выполнение задач из .kiro/specs/auth-feature/tasks.md
Система: ✅ Запускаю выполнение задач из файла .kiro/specs/auth-feature/tasks.md
```

### Формат файла tasks.md

Файл tasks.md должен содержать секцию `## Задачи` с задачами в формате markdown чекбоксов:

```markdown
# План реализации: Моя функция

## Задачи

- [ ] 1. Первая задача
  - [ ] 1.1 Подзадача 1.1
  - [ ] 1.2 Подзадача 1.2
  - _Требования: 1.1, 1.2_

- [ ] 2. Вторая задача
  - [ ] 2.1 Подзадача 2.1

- [ ]* 3. Опциональная задача (будет пропущена по умолчанию)

- [ ] 4. Checkpoint - Контрольная точка

- [ ] 5. Финальная задача
```

**Типы чекбоксов:**
- `- [ ]` - незавершенная задача
- `- [x]` - завершенная задача
- `- [ ]*` - опциональная задача (пропускается при `skipOptional=true`)

**Специальные задачи:**
- Задачи с текстом "Checkpoint" или "Контрольная точка" останавливают выполнение для подтверждения пользователя

### Запуск агентского режима

**Через API:**

```bash
POST /api/dialogues/{id}/execute-tasks
Content-Type: application/json

{
  "tasksFilePath": "C:/Projects/MyProject/tasks.md",
  "skipOptional": true
}
```

**Ответ:** `202 Accepted` с ID сессии выполнения

### Управление выполнением

**Остановка выполнения:**

```bash
POST /api/dialogues/{id}/stop-execution
```

Система завершит текущую задачу и остановит выполнение. Статус сессии изменится на `stopped`.

**Продолжение выполнения:**

```bash
POST /api/dialogues/{id}/resume-execution
```

Система продолжит выполнение с первой незавершенной задачи.

**Проверка статуса:**

```bash
GET /api/dialogues/{id}/execution-status
```

**Ответ:**
```json
{
  "status": "running",
  "progress": "3/10",
  "currentTask": "1.2 Подзадача 1.2",
  "errorMessage": null,
  "startedAt": "2026-02-26T14:30:00Z",
  "completedAt": null
}
```

**Возможные статусы:**
- `none` - выполнение не запущено
- `running` - выполнение в процессе
- `paused` - остановлено на контрольной точке
- `stopped` - остановлено пользователем
- `completed` - все задачи выполнены
- `failed` - выполнение прервано из-за ошибки

### Особенности выполнения

1. **Порядок выполнения:** Задачи выполняются в порядке следования в файле. Подзадачи выполняются перед родительской задачей.

2. **Git чекпоинты:** Перед каждой задачей создается Git чекпоинт с описанием `"Agent: Task [текст задачи]"`.

3. **Обновление файла:** После успешного выполнения задачи её статус в файле tasks.md обновляется с `[ ]` на `[x]`.

4. **Резервные копии:** Перед каждым обновлением файла tasks.md создается резервная копия с timestamp.

5. **Сообщения о прогрессе:** Система сохраняет сообщения в диалог:
   - `🤖 Начинаю выполнение задачи N из M: [текст]`
   - `✅ Задача выполнена за X.Xс`
   - `❌ Ошибка при выполнении задачи: [текст ошибки]`
   - `⏸️ Выполнение остановлено пользователем`
   - `▶️ Продолжаю выполнение задач...`

6. **Таймаут:** Каждая задача имеет таймаут 5 минут. При превышении выполнение останавливается.

7. **Обработка ошибок:** При ошибке выполнения задачи система останавливает выполнение последующих задач и сохраняет информацию об ошибке.

### Пример использования

```bash
# 1. Создать диалог для проекта
curl -X POST http://localhost:5000/api/dialogues \
  -H "Content-Type: application/json" \
  -d '{"projectPath": "C:/Projects/MyProject"}'

# Ответ: {"id": 1, "projectPath": "C:/Projects/MyProject", ...}

# 2. Запустить выполнение задач
curl -X POST http://localhost:5000/api/dialogues/1/execute-tasks \
  -H "Content-Type: application/json" \
  -d '{"tasksFilePath": "C:/Projects/MyProject/tasks.md", "skipOptional": true}'

# Ответ: 202 Accepted, {"sessionId": 1}

# 3. Проверить статус
curl http://localhost:5000/api/dialogues/1/execution-status

# 4. Остановить выполнение (если нужно)
curl -X POST http://localhost:5000/api/dialogues/1/stop-execution

# 5. Продолжить выполнение
curl -X POST http://localhost:5000/api/dialogues/1/resume-execution
```

## Архитектура

### Компоненты

- **Frontend**: HTML/JavaScript веб-интерфейс
- **Backend**: ASP.NET Core 10 Minimal API
- **Database**: SQLite с Entity Framework Core
- **MCP Client**: JSON-RPC 2.0 клиент для Serena
- **LLM Service**: Интеграция с OpenAI API (DeepSeek)
- **Git Service**: Управление версиями и чекпоинтами

### Поток обработки запроса

1. Пользователь вводит команду в чат
2. Создается Git чекпоинт (коммит)
3. Команда отправляется в LLM с описанием доступных инструментов Serena
4. LLM возвращает последовательность вызовов инструментов
5. Инструменты выполняются через Serena MCP Server
6. Результаты сохраняются в базу данных и отображаются пользователю

## API Endpoints

### Диалоги

- `POST /api/dialogues` - Создать новый диалог
- `GET /api/dialogues` - Получить список всех диалогов
- `GET /api/dialogues/{id}` - Получить диалог с сообщениями и чекпоинтами
- `DELETE /api/dialogues/{id}` - Удалить диалог

### Сообщения

- `POST /api/dialogues/{id}/messages` - Отправить сообщение в диалог

### Чекпоинты

- `GET /api/dialogues/{id}/checkpoints` - Получить список чекпоинтов
- `POST /api/dialogues/{id}/checkpoints` - Создать чекпоинт вручную
- `POST /api/dialogues/{id}/rollback` - Откатить проект к чекпоинту

### Агентский режим

- `POST /api/dialogues/{id}/execute-tasks` - Запустить выполнение задач из файла tasks.md
- `POST /api/dialogues/{id}/stop-execution` - Остановить текущее выполнение
- `POST /api/dialogues/{id}/resume-execution` - Продолжить выполнение с места остановки
- `GET /api/dialogues/{id}/execution-status` - Получить статус текущего выполнения

### Конфигурация

- `GET /api/configuration` - Получить текущую конфигурацию LLM
- `POST /api/configuration` - Сохранить конфигурацию LLM
- `POST /api/configuration/test` - Проверить подключение к LLM
- `GET /api/configuration/ollama/models` - Получить список доступных моделей Ollama

### Проекты

- `GET /api/projects` - Получить список всех проектов
- `GET /api/projects/selected` - Получить выбранный проект
- `POST /api/projects` - Добавить новый проект
- `DELETE /api/projects/{id}` - Удалить проект
- `POST /api/projects/{id}/select` - Выбрать проект

### Валидация

- `GET /api/startup/validate` - Проверить подключение к LLM при запуске

## Безопасность

- Валидация путей к проектам (только абсолютные пути)
- Опциональное ограничение корневой директории через `AllowedRootDirectory`
- Санитизация путей для предотвращения command injection
- Проверка незакоммиченных изменений перед откатом

## Устранение неполадок

### Serena MCP Server недоступен

Если при запуске появляется ошибка инициализации MCP Client:

1. Проверьте, что Docker контейнер с Serena запущен: `docker ps`
2. Проверьте настройки в `appsettings.json` (StdioCommand и StdioArgs)
3. Убедитесь, что имя контейнера совпадает с указанным в конфигурации

### Ошибки LLM API

Если запросы к LLM не работают:

1. Проверьте правильность API ключа в `appsettings.json`
2. Убедитесь, что у вас есть доступ к API (проверьте баланс/лимиты)
3. Проверьте BaseUrl для вашего провайдера

### Git ошибки

Если возникают проблемы с Git:

1. Убедитесь, что Git установлен и доступен в PATH
2. Проверьте права доступа к папке проекта
3. Убедитесь, что нет незакоммиченных изменений перед откатом

### Проблемы с агентским режимом

**Файл tasks.md не найден:**
- Убедитесь, что файл существует в корне проекта или укажите полный путь
- Проверьте правильность пути: используйте относительный путь от корня проекта
- Пример: `.kiro/specs/feature/tasks.md` вместо `C:/Projects/MyProject/.kiro/specs/feature/tasks.md`

**Выполнение не запускается:**
- Проверьте формат файла tasks.md (должна быть секция `## Задачи`)
- Убедитесь, что есть незавершенные задачи (чекбоксы `- [ ]`)
- Проверьте, что нет уже запущенного выполнения (команда `покажи статус`)

**Выполнение останавливается с ошибкой:**
- Проверьте сообщение об ошибке в чате
- Убедитесь, что LLM API доступен и работает
- Проверьте, что проект является Git репозиторием
- Попробуйте возобновить выполнение командой `продолжи выполнение`

**Кнопки управления не отображаются:**
- Обновите страницу браузера (F5)
- Проверьте консоль браузера на наличие ошибок (F12)
- Убедитесь, что выполнение действительно запущено (команда `статус`)

**Индикатор прогресса не обновляется:**
- Проверьте подключение к интернету
- Обновите страницу браузера
- Проверьте консоль браузера на наличие ошибок сети

**Сообщения о прогрессе не появляются:**
- Подождите несколько секунд - система обновляет сообщения каждые 2 секунды
- Обновите страницу браузера
- Проверьте, что диалог активен (выбран в левой панели)
