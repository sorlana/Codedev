# Руководство по агентскому режиму

## Обзор

Агентский режим (Agent Task Executor) - это функция автоматического выполнения задач из файла `tasks.md`. Система последовательно обрабатывает незавершенные задачи, отправляя их в LLM через существующий PromptProcessor, создает Git чекпоинты перед каждой задачей и отслеживает прогресс выполнения.

## Основные возможности

- ✅ Автоматическое последовательное выполнение задач
- ✅ Поддержка иерархических задач (задачи и подзадачи)
- ✅ Создание Git чекпоинтов перед каждой задачей
- ✅ Автоматическое обновление статусов в файле tasks.md
- ✅ Отслеживание прогресса выполнения
- ✅ Управление выполнением (остановка/продолжение)
- ✅ Обработка ошибок и таймаутов
- ✅ Резервное копирование файла tasks.md
- ✅ Контрольные точки для ручной проверки

## Формат файла tasks.md

### Базовая структура

Файл tasks.md должен содержать секцию `## Задачи` с задачами в формате markdown чекбоксов:

```markdown
# План реализации: Название функции

## Обзор

Краткое описание функции (опционально)

## Задачи

- [ ] 1. Первая задача
  - [ ] 1.1 Подзадача 1.1
  - [ ] 1.2 Подзадача 1.2
  - _Требования: 1.1, 1.2, 1.3_

- [ ] 2. Вторая задача
  - [ ] 2.1 Подзадача 2.1
  - _Требования: 2.1_

- [ ]* 3. Опциональная задача

- [ ] 4. Checkpoint - Контрольная точка

- [ ] 5. Финальная задача
```

### Типы чекбоксов

| Формат | Описание | Поведение |
|--------|----------|-----------|
| `- [ ]` | Незавершенная задача | Будет выполнена |
| `- [x]` | Завершенная задача | Будет пропущена |
| `- [ ]*` | Опциональная задача | Пропускается при `skipOptional=true` |
| `- [-]` | В процессе выполнения | Обрабатывается как незавершенная |

### Иерархия задач

Система поддерживает вложенные подзадачи:

```markdown
- [ ] 1. Родительская задача
  - [ ] 1.1 Подзадача уровня 1
    - [ ] 1.1.1 Подзадача уровня 2
  - [ ] 1.2 Подзадача уровня 1
```

**Правила выполнения:**
- Подзадачи выполняются перед родительской задачей
- Родительская задача помечается как завершенная только после выполнения всех подзадач
- Порядок выполнения: 1.1 → 1.1.1 → 1.2 → 1

### Метаданные задач

**Требования:**

Можно указать ссылки на требования из документа requirements.md:

```markdown
- [ ] 1. Реализовать аутентификацию
  - _Требования: 1.1, 1.2, 1.3_
```

Эти требования будут включены в промпт для LLM.

### Контрольные точки

Задачи, содержащие слова "Checkpoint" или "Контрольная точка", останавливают автоматическое выполнение:

```markdown
- [ ] 4. Checkpoint - Проверить результаты перед продолжением
```

При достижении такой задачи:
1. Система останавливает выполнение
2. Статус сессии меняется на `paused`
3. Сохраняется сообщение: "🛑 Достигнута контрольная точка. Требуется подтверждение пользователя."
4. Пользователь может проверить результаты и продолжить выполнение вручную

## API для работы с агентским режимом

### 1. Запуск выполнения задач

**Endpoint:** `POST /api/dialogues/{id}/execute-tasks`

**Тело запроса:**
```json
{
  "tasksFilePath": "C:/Projects/MyProject/tasks.md",
  "skipOptional": true
}
```

**Параметры:**
- `tasksFilePath` (обязательный) - абсолютный путь к файлу tasks.md
- `skipOptional` (опциональный, по умолчанию `true`) - пропускать ли опциональные задачи

**Ответ:** `202 Accepted`
```json
{
  "sessionId": 1
}
```

**Возможные ошибки:**
- `404 Not Found` - диалог не найден
- `400 Bad Request` - файл tasks.md не найден или путь невалиден

### 2. Остановка выполнения

**Endpoint:** `POST /api/dialogues/{id}/stop-execution`

**Ответ:** `200 OK`
```json
{
  "message": "Execution stopped"
}
```

**Поведение:**
- Система завершит текущую задачу
- Статус сессии изменится на `stopped`
- Сохранится сообщение: "⏸️ Выполнение остановлено пользователем. Выполнено N из M задач"

### 3. Продолжение выполнения

**Endpoint:** `POST /api/dialogues/{id}/resume-execution`

**Ответ:** `202 Accepted`
```json
{
  "message": "Execution resumed"
}
```

**Поведение:**
- Система перепарсит файл tasks.md
- Продолжит выполнение с первой незавершенной задачи
- Статус сессии изменится на `running`
- Сохранится сообщение: "▶️ Продолжаю выполнение задач..."

**Возможные ошибки:**
- `400 Bad Request` - нет остановленной сессии для продолжения

### 4. Проверка статуса выполнения

**Endpoint:** `GET /api/dialogues/{id}/execution-status`

**Ответ:** `200 OK`
```json
{
  "status": "running",
  "progress": "3/10",
  "currentTask": "1.2 Подзадача 1.2",
  "errorMessage": null,
  "startedAt": "2026-02-26T14:30:00Z",
  "completedAt": null
}
```

**Поля ответа:**
- `status` - текущий статус выполнения (см. ниже)
- `progress` - прогресс в формате "N/M" (выполнено/всего)
- `currentTask` - текст текущей задачи (или последней выполненной)
- `errorMessage` - текст ошибки (если есть)
- `startedAt` - время начала выполнения
- `completedAt` - время завершения (если завершено)

**Возможные статусы:**
- `none` - выполнение не запущено
- `running` - выполнение в процессе
- `paused` - остановлено на контрольной точке
- `stopped` - остановлено пользователем
- `completed` - все задачи выполнены успешно
- `failed` - выполнение прервано из-за ошибки

## Процесс выполнения задач

### Жизненный цикл выполнения

```
1. Запуск (execute-tasks)
   ↓
2. Парсинг tasks.md
   ↓
3. Создание ExecutionSession (status: running)
   ↓
4. Для каждой задачи:
   ├─ Создание Git чекпоинта
   ├─ Сохранение стартового сообщения
   ├─ Формирование промпта
   ├─ Отправка в PromptProcessor
   ├─ Обработка результата
   ├─ Обновление статуса в файле
   └─ Сохранение финального сообщения
   ↓
5. Завершение (status: completed/failed/stopped)
```

### Формирование промпта для задачи

Для каждой задачи система формирует промпт следующего формата:

```
Выполни следующую задачу из плана реализации:

**Задача:** 1.2 Реализовать метод валидации

**Подзадачи:**
  - 1.2.1 Добавить проверку на null
  - 1.2.2 Добавить проверку формата email

**Требования:** 1.1, 1.2, 1.3

После выполнения сообщи о результате.
```

### Обновление файла tasks.md

После успешного выполнения задачи:

1. Создается резервная копия файла с timestamp: `tasks.md.backup_20260226143000`
2. Статус задачи обновляется: `- [ ]` → `- [x]`
3. Сохраняется отступ и все остальное содержимое файла

**Пример:**

До:
```markdown
- [ ] 1. Первая задача
  - [ ] 1.1 Подзадача 1.1
  - [ ] 1.2 Подзадача 1.2
```

После выполнения 1.1:
```markdown
- [ ] 1. Первая задача
  - [x] 1.1 Подзадача 1.1
  - [ ] 1.2 Подзадача 1.2
```

### Git чекпоинты

Перед каждой задачей создается Git чекпоинт:

**Формат описания:** `Agent: Task [первые 50 символов текста задачи]`

**Пример:**
```
Agent: Task 1.1 Подзадача 1.1
Agent: Task 1.2 Подзадача 1.2
Agent: Task 2.1 Подзадача 2.1
```

Чекпоинты сохраняются в базу данных и связываются с диалогом, что позволяет откатить изменения через API.

### Сообщения о прогрессе

Система сохраняет сообщения в диалог на каждом этапе:

| Событие | Формат сообщения |
|---------|------------------|
| Начало задачи | `🤖 Начинаю выполнение задачи N из M: [текст задачи]` |
| Успешное завершение | `✅ Задача выполнена за X.Xс` |
| Ошибка выполнения | `❌ Ошибка при выполнении задачи: [текст ошибки]` |
| Таймаут | `❌ Превышено время выполнения задачи (5 минут)` |
| Контрольная точка | `🛑 Достигнута контрольная точка. Требуется подтверждение пользователя.` |
| Остановка | `⏸️ Выполнение остановлено пользователем. Выполнено N из M задач` |
| Продолжение | `▶️ Продолжаю выполнение задач...` |
| Завершение | `✅ Все задачи выполнены успешно. Выполнено N из M задач за X.X минут` |

## Обработка ошибок

### Ошибки валидации

При запуске выполнения проверяются:

1. **Существование диалога** - если диалог не найден, возвращается `404 Not Found`
2. **Существование файла** - если файл tasks.md не найден, возвращается `400 Bad Request`
3. **Валидность пути** - путь проверяется через PathValidator

### Ошибки выполнения задач

**Ошибка от PromptProcessor:**
- Выполнение останавливается
- Статус сессии: `failed`
- Сохраняется текст ошибки в `errorMessage`
- Создается сообщение: "❌ Ошибка при выполнении задачи: [текст]"

**Таймаут задачи (>5 минут):**
- Выполнение останавливается
- Статус сессии: `failed`
- Сохраняется ошибка: "Task execution timeout (5 minutes)"
- Создается сообщение: "❌ Превышено время выполнения задачи (5 минут)"

### Ошибки создания чекпоинтов

Если не удается создать Git чекпоинт:
- Записывается предупреждение в лог
- Выполнение продолжается (не критическая ошибка)

### Ошибки обновления файла

Если не удается обновить файл tasks.md:
- Записывается ошибка в лог
- Выполнение продолжается (не критическая ошибка)
- Резервная копия сохраняется перед попыткой обновления

## Восстановление и резервные копии

### Резервные копии файла tasks.md

Перед каждым обновлением файла создается резервная копия:

**Формат имени:** `tasks.md.backup_yyyyMMddHHmmss`

**Пример:**
```
tasks.md.backup_20260226143051
tasks.md.backup_20260226143052
tasks.md.backup_20260226143053
```

### Восстановление из резервной копии

Вручную скопируйте нужную резервную копию:

```bash
# Windows
copy tasks.md.backup_20260226143051 tasks.md

# Linux/Mac
cp tasks.md.backup_20260226143051 tasks.md
```

### Откат через Git чекпоинты

Используйте API для отката к чекпоинту:

```bash
# 1. Получить список чекпоинтов
curl http://localhost:5000/api/dialogues/1/checkpoints

# 2. Откатить к нужному чекпоинту
curl -X POST http://localhost:5000/api/dialogues/1/rollback \
  -H "Content-Type: application/json" \
  -d '{"checkpointId": 5}'
```

## Примеры использования

### Пример 1: Простое выполнение

```bash
# Создать диалог
curl -X POST http://localhost:5000/api/dialogues \
  -H "Content-Type: application/json" \
  -d '{"projectPath": "C:/Projects/MyProject"}'

# Запустить выполнение
curl -X POST http://localhost:5000/api/dialogues/1/execute-tasks \
  -H "Content-Type: application/json" \
  -d '{"tasksFilePath": "C:/Projects/MyProject/tasks.md"}'

# Проверить статус
curl http://localhost:5000/api/dialogues/1/execution-status
```

### Пример 2: Выполнение с остановкой и продолжением

```bash
# Запустить выполнение
curl -X POST http://localhost:5000/api/dialogues/1/execute-tasks \
  -H "Content-Type: application/json" \
  -d '{"tasksFilePath": "C:/Projects/MyProject/tasks.md"}'

# Подождать немного...
sleep 5

# Остановить выполнение
curl -X POST http://localhost:5000/api/dialogues/1/stop-execution

# Проверить статус (должен быть "stopped")
curl http://localhost:5000/api/dialogues/1/execution-status

# Продолжить выполнение
curl -X POST http://localhost:5000/api/dialogues/1/resume-execution
```

### Пример 3: Выполнение с опциональными задачами

```bash
# Выполнить все задачи, включая опциональные
curl -X POST http://localhost:5000/api/dialogues/1/execute-tasks \
  -H "Content-Type: application/json" \
  -d '{"tasksFilePath": "C:/Projects/MyProject/tasks.md", "skipOptional": false}'
```

## Тестирование

### Интеграционный тест

Запустите полный интеграционный тест:

```bash
dotnet run test-integration
```

Тест проверяет:
- ✅ Создание тестового проекта с Git
- ✅ Парсинг файла tasks.md
- ✅ Запуск выполнения задач
- ✅ Создание Git чекпоинтов
- ✅ Обновление статусов в файле
- ✅ Сохранение сообщений в диалоге
- ✅ Создание резервных копий
- ✅ Остановку на контрольной точке
- ✅ Остановку и продолжение выполнения

### Ручное тестирование

1. Создайте тестовый файл tasks.md:

```markdown
# План реализации: Тест

## Задачи

- [ ] 1. Первая задача
  - [ ] 1.1 Подзадача 1.1
  - [ ] 1.2 Подзадача 1.2

- [ ] 2. Вторая задача

- [ ]* 3. Опциональная задача

- [ ] 4. Checkpoint - Контрольная точка

- [ ] 5. Финальная задача
```

2. Запустите приложение:

```bash
dotnet run
```

3. Создайте диалог через веб-интерфейс или API

4. Запустите выполнение задач

5. Наблюдайте за прогрессом в веб-интерфейсе

## Лучшие практики

### Структура задач

1. **Разбивайте большие задачи на подзадачи** - это упрощает выполнение и отслеживание прогресса

2. **Используйте контрольные точки** - добавляйте checkpoint после важных этапов для ручной проверки

3. **Указывайте требования** - это помогает LLM понять контекст задачи

4. **Делайте задачи атомарными** - каждая задача должна быть независимой и выполнимой за разумное время

### Управление выполнением

1. **Мониторьте прогресс** - регулярно проверяйте статус выполнения

2. **Проверяйте результаты** - используйте контрольные точки для проверки промежуточных результатов

3. **Сохраняйте резервные копии** - система создает их автоматически, но можно делать дополнительные вручную

4. **Используйте Git** - все изменения сохраняются в чекпоинтах, что позволяет легко откатить изменения

### Обработка ошибок

1. **Проверяйте логи** - при ошибках смотрите логи приложения для деталей

2. **Используйте resume** - если выполнение прервалось, можно продолжить с места остановки

3. **Откатывайте изменения** - при проблемах используйте Git чекпоинты для отката

## Ограничения

1. **Таймаут задачи** - максимальное время выполнения одной задачи: 5 минут

2. **Последовательное выполнение** - задачи выполняются строго последовательно, параллельное выполнение не поддерживается

3. **Формат файла** - поддерживается только формат markdown с чекбоксами

4. **Секция задач** - задачи должны быть в секции `## Задачи`, задачи вне этой секции игнорируются

5. **Резервные копии** - создаются с точностью до секунды, быстрое выполнение может создать конфликты имен

## Устранение неполадок

### Выполнение не запускается

**Проблема:** Запрос возвращает 404 или 400

**Решение:**
- Проверьте, что диалог существует
- Проверьте путь к файлу tasks.md (должен быть абсолютным)
- Убедитесь, что файл tasks.md существует

### Задачи не выполняются

**Проблема:** Статус остается "running", но прогресс не меняется

**Решение:**
- Проверьте логи приложения на наличие ошибок
- Убедитесь, что LLM сервис доступен
- Проверьте, что в файле tasks.md есть незавершенные задачи

### Файл tasks.md не обновляется

**Проблема:** Статусы задач не меняются в файле

**Решение:**
- Проверьте права доступа к файлу
- Проверьте логи на наличие ошибок записи
- Убедитесь, что файл не открыт в другом приложении

### Резервные копии конфликтуют

**Проблема:** Ошибка "The file already exists" при создании резервной копии

**Решение:**
- Это происходит при быстром выполнении задач (несколько в одну секунду)
- Не критично - выполнение продолжается
- Можно вручную удалить старые резервные копии
