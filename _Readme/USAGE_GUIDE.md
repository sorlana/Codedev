# Руководство по использованию C# Refactoring Assistant

## Как работать с приложением

### Real-time функции

Приложение использует современные технологии для мгновенной коммуникации и оптимальной производительности:

#### WebSocket соединение

**Автоматическое подключение:**
- WebSocket соединение устанавливается автоматически при выборе диалога
- Индикатор статуса в правом верхнем углу показывает текущее состояние:
  - 🟢 **WebSocket** - активное соединение, мгновенные обновления
  - 🟡 **HTTP** - fallback режим, обновления через polling
  - 🔴 **Отключено** - нет соединения с сервером

**Автоматическое переподключение:**
- При разрыве соединения система автоматически пытается переподключиться
- Используется экспоненциальная задержка: 1с, 2с, 4с, 8с (максимум 30с)
- После 5 неудачных попыток система переключается на HTTP режим
- При восстановлении соединения автоматически синхронизируются пропущенные сообщения

#### Потоковая передача ответов (Streaming)

**Как это работает:**
- Ответы LLM отображаются по мере генерации, а не после завершения
- Вы видите текст появляющимся в реальном времени, как при печати
- Это значительно улучшает восприятие скорости работы

**Кнопка "Остановить генерацию":**
- Появляется во время генерации ответа
- Позволяет прервать длинные ответы, если вы получили нужную информацию
- Частичный ответ сохраняется и остается доступным

**Обработка ошибок:**
- При ошибке во время streaming частичный ответ сохраняется
- Отображается сообщение об ошибке с возможностью повторить запрос
- При разрыве соединения система пытается возобновить передачу

#### Кэширование сообщений

**Мгновенная загрузка истории:**
- Сообщения кэшируются в localStorage браузера
- При переключении диалогов история отображается мгновенно (< 100ms)
- Затем в фоне загружаются обновления с сервера

**Автоматическое управление кэшем:**
- Хранится до 100 последних сообщений на диалог
- Максимальный размер кэша: 5MB
- Сообщения старше 24 часов автоматически удаляются
- При превышении лимита удаляются самые старые сообщения

**Синхронизация:**
- Новые сообщения автоматически добавляются в кэш
- Кэш обновляется при получении изменений с сервера
- Работает прозрачно, не требует действий пользователя

#### Виртуализация списка сообщений

**Плавная прокрутка больших диалогов:**
- Для диалогов с более чем 50 сообщениями используется виртуализация
- Рендерятся только видимые сообщения + буфер (10 сверху и снизу)
- Обеспечивает плавную прокрутку даже для тысяч сообщений (60 FPS)

**Автоматическая подгрузка истории:**
- При прокрутке к началу диалога автоматически загружаются предыдущие сообщения
- Порог подгрузки: 20 сообщений от начала
- Позиция прокрутки сохраняется после загрузки

**Поиск по сообщениям:**
- Поиск работает по всем сообщениям, включая не отрендеренные
- Система автоматически прокручивает к первому найденному результату
- Найденное сообщение подсвечивается на 2 секунды

**Автопрокрутка к новым сообщениям:**
- Если вы находитесь в пределах 100px от конца списка, новые сообщения автоматически прокручиваются в видимую область
- Если вы читаете старые сообщения, автопрокрутка не происходит

#### Автосохранение черновиков

**Автоматическое сохранение:**
- Текст в поле ввода автоматически сохраняется через 2 секунды после последнего нажатия клавиши
- Используется debouncing для оптимизации производительности
- Пустые черновики не сохраняются

**Переключение между диалогами:**
- При переключении диалога текущий черновик сохраняется немедленно
- Черновик нового диалога автоматически загружается в поле ввода
- Каждый диалог имеет свой независимый черновик

**Восстановление после перезагрузки:**
- При перезагрузке страницы черновик автоматически восстанавливается
- Вы не потеряете текст даже при случайном закрытии вкладки

**Автоматическая очистка:**
- После отправки сообщения черновик удаляется
- Черновики старше 7 дней автоматически удаляются при запуске приложения

#### Режим отладки

Для разработчиков и диагностики проблем доступен режим отладки:

**Включение:**
```javascript
// Откройте консоль браузера (F12) и выполните:
localStorage.setItem('DEBUG_MODE', 'true');
location.reload();
```

**Отображаемые метрики:**
- TTFB (Time To First Byte) для streaming - время до первого фрагмента ответа
- FPS прокрутки - частота обновления при прокрутке списка
- Размер кэша - количество сообщений и занимаемый объем
- События WebSocket - подключение, разрыв, переподключение
- Операции с кэшем - добавление, удаление, очистка

**Отключение:**
```javascript
localStorage.removeItem('DEBUG_MODE');
location.reload();
```

### 3. Работа с чекпоинтами

Приложение автоматически создает Git чекпоинты перед каждым изменением кода:

- **Автоматические чекпоинты**: Создаются перед каждой командой ИИ
- **Откат**: Нажмите "Откатить" на любом чекпоинте в правой панели
- **История**: Все чекпоинты сохраняются с описанием команды

### 4. Агентский режим выполнения задач

Агентский режим позволяет автоматически выполнять последовательность задач из файла `tasks.md` прямо через чат.

#### Как использовать:

1. **Создайте файл tasks.md** в корне вашего проекта или в подпапке (например, `.kiro/specs/feature/tasks.md`)

2. **Запустите выполнение** через команду в чате:
   ```
   начни выполнение задач из tasks.md
   ```
   или с указанием пути:
   ```
   начни выполнение задач из .kiro/specs/auth/tasks.md
   ```

3. **Наблюдайте за прогрессом** в реальном времени:
   - Индикатор прогресса показывает текущий статус (🔄 Выполняется... 3/10 задач)
   - Сообщения о каждом шаге появляются в чате
   - Кнопка "Остановить" позволяет прервать выполнение

4. **Управляйте выполнением**:
   - Нажмите кнопку "Остановить" или напишите `останови выполнение`
   - Для продолжения нажмите "Возобновить" или напишите `продолжи выполнение`
   - Проверьте статус командой `покажи статус`

#### Визуальные элементы:

**Индикатор прогресса:**
- 🔄 Выполняется... (3/10 задач) - идет выполнение
- ⏸️ Приостановлено (3/10 задач) - выполнение остановлено
- ✅ Завершено (10/10 задач) - все задачи выполнены
- ❌ Ошибка - произошла ошибка

**Кнопки управления:**
- **Остановить** (красная) - останавливает выполнение после текущей задачи
- **Возобновить** (зеленая) - продолжает выполнение с места остановки

**Сообщения о прогрессе:**
- 🤖 Начинаю выполнение задачи...
- 📌 Создаю чекпоинт...
- 🧠 Отправляю задачу в LLM...
- ✅ Задача выполнена за X.Xс
- 📝 Обновляю статус задачи в файле
- ❌ Ошибка: [описание]
- 🎉 Все задачи выполнены успешно!

#### Формат файла с задачами:

Файл с задачами (tasks.md, feature-plan.md, implementation.md и т.д.) должен содержать секцию `## Задачи` с задачами в формате markdown чекбоксов:
# План реализации: Моя функция

## Задачи

- [ ] 1. Первая задача
  - [ ] 1.1 Подзадача 1.1
  - [ ] 1.2 Подзадача 1.2

- [ ] 2. Вторая задача
  - [ ] 2.1 Подзадача 2.1

- [ ]* 3. Опциональная задача (пропускается)

- [ ] 4. Checkpoint - Контрольная точка

- [ ] 5. Финальная задача
```

**Типы задач:**
- `- [ ]` - обычная задача
- `- [x]` - завершенная задача (пропускается)
- `- [ ]*` - опциональная задача (пропускается)
- Задачи с "Checkpoint" - останавливают выполнение для подтверждения

## Советы по использованию

### ✅ Хорошие практики:

1. **Будьте конкретны**: "Переименуй метод GetUser в FetchUserData" лучше, чем "Измени метод"

2. **Указывайте контекст**: "В классе UserService переименуй метод..." лучше, чем просто "Переименуй метод..."

3. **Проверяйте изменения**: После каждой команды проверяйте результат в вашей IDE

4. **Используйте чекпоинты**: Если что-то пошло не так, откатитесь к предыдущему чекпоинту

5. **Разбивайте задачи**: Лучше несколько простых команд, чем одна сложная

### ⚠️ Ограничения:

1. **Windows команды**: Приложение автоматически конвертирует Linux команды в Windows, но лучше использовать Windows синтаксис:
   - `dir` вместо `ls`
   - `type` вместо `cat`
   - `copy` вместо `cp`

2. **Пути к файлам**: Используйте относительные пути от корня проекта

3. **Большие изменения**: Для масштабных рефакторингов лучше разбить на несколько шагов

4. **Тестирование**: Всегда тестируйте код после изменений

## Устранение неполадок

### Проблемы с real-time функциями

#### WebSocket не подключается

**Симптомы:**
- Индикатор показывает 🔴 Отключено или 🟡 HTTP
- Сообщения приходят с задержкой
- В консоли браузера ошибки WebSocket

**Решение:**
1. Откройте консоль браузера (F12) и проверьте ошибки WebSocket
2. Убедитесь, что приложение запущено и доступно по указанному порту
3. Проверьте, что порт не блокируется брандмауэром или антивирусом
4. Попробуйте другой браузер (Chrome, Firefox, Edge)
5. Если используете прокси, убедитесь, что он поддерживает WebSocket
6. Система автоматически переключится на HTTP режим после 5 неудачных попыток

**Проверка WebSocket в консоли:**
```javascript
// Откройте консоль браузера (F12) и выполните:
const ws = new WebSocket('ws://localhost:5000/ws?dialogueId=1');
ws.onopen = () => console.log('WebSocket подключен');
ws.onerror = (e) => console.error('Ошибка WebSocket:', e);
```

#### Streaming не работает

**Симптомы:**
- Ответы появляются целиком, а не по частям
- Кнопка "Остановить генерацию" не появляется
- Долгое ожидание перед появлением ответа

**Решение:**
1. Проверьте статус WebSocket соединения (должен быть 🟢)
2. Убедитесь, что LLM провайдер поддерживает streaming:
   - OpenAI: поддерживает (GPT-4, GPT-3.5)
   - DeepSeek: поддерживает
   - Ollama: поддерживает
3. Проверьте консоль браузера на наличие ошибок
4. Попробуйте отправить простой запрос: "Привет"
5. При недоступности streaming система автоматически покажет полный ответ

#### Кэш не работает (медленная загрузка истории)

**Симптомы:**
- История диалога загружается медленно при переключении
- Сообщения не отображаются мгновенно
- В консоли ошибки localStorage

**Решение:**
1. Проверьте доступность localStorage:
   ```javascript
   // В консоли браузера (F12):
   try {
     localStorage.setItem('test', 'test');
     localStorage.removeItem('test');
     console.log('localStorage доступен');
   } catch (e) {
     console.error('localStorage недоступен:', e);
   }
   ```

2. Убедитесь, что браузер не в приватном режиме (localStorage может быть отключен)

3. Проверьте квоту localStorage:
   ```javascript
   // Проверка размера кэша:
   let total = 0;
   for (let key in localStorage) {

#### Режим отладки для диагностики

Если проблемы продолжаются, включите режим отладки:

```javascript
// В консоли браузера (F12):
localStorage.setItem('DEBUG_MODE', 'true');
location.reload();
```

**Что показывает режим отладки:**
- 📊 TTFB: время до первого фрагмента ответа (должно быть < 1000ms)
- 🎯 FPS: частота обновления при прокрутке (должно быть ≥ 60)
- 💾 Кэш: размер и количество сообщений
- 🔌 WebSocket: события подключения/разрыва
- ⚠️ Предупреждения: если производительность падает

**Интерпретация метрик:**
- TTFB > 2000ms: медленное соединение или перегруженный сервер
- FPS < 30: проблемы с производительностью браузера
- Размер кэша > 4MB: скоро будет автоматическая очистка
- Частые разрывы WebSocket: проблемы с сетью

**Отключение режима отладки:**
```javascript
localStorage.removeItem('DEBUG_MODE');
location.reload();
```

- Проверьте правильность API ключа
- Убедитесь, что у вас есть доступ к API
- Проверьте баланс аккаунта (для платных API)

### Проблемы с агентским режимом

**Файл tasks.md не найден:**
- Убедитесь, что файл существует в корне проекта
- Если файл в подпапке, укажите относительный путь: `.kiro/specs/feature/tasks.md`
- Не используйте абсолютные пути (C:/...), только относительные от корня проекта

**Команда не распознается:**
- Используйте точные формулировки: "начни выполнение задач из tasks.md"
- Попробуйте английский вариант: "execute tasks from tasks.md"
- Проверьте, что команда написана без опечаток

**Выполнение не запускается:**
- Проверьте формат файла с задачами (должна быть секция `## Задачи`)
- Убедитесь, что есть незавершенные задачи с чекбоксами `- [ ]`
- Проверьте статус командой `покажи статус` - возможно, выполнение уже запущено

**Выполнение останавливается с ошибкой:**
- Прочитайте сообщение об ошибке в чате (начинается с ❌)
- Проверьте, что LLM API доступен и работает
- Убедитесь, что проект является Git репозиторием
- Попробуйте возобновить выполнение: `продолжи выполнение`

**Кнопки управления не отображаются:**
- Обновите страницу браузера (F5)
- Откройте консоль браузера (F12) и проверьте наличие ошибок JavaScript
- Убедитесь, что выполнение действительно запущено командой `статус`
- Проверьте, что вы находитесь в правильном диалоге

**Индикатор прогресса не обновляется:**
- Подождите 2-3 секунды - система обновляет статус каждые 2 секунды
- Проверьте подключение к интернету
- Обновите страницу браузера
- Откройте консоль браузера (F12) и проверьте наличие ошибок сети

**Сообщения о прогрессе не появляются:**
- Система обновляет сообщения автоматически каждые 2 секунды
- Обновите страницу браузера
- Проверьте, что диалог активен (выбран в левой панели)
- Убедитесь, что выполнение действительно запущено

**Выполнение "зависло":**
- Проверьте статус командой `покажи статус`
- Если статус "running", подождите - задача может выполняться долго
- Если прошло более 5 минут, остановите выполнение: `останови выполнение`
- Проверьте логи в консоли приложения на наличие ошибок

- API ключи хранятся в `appsettings.json`

- Рекомендуется не коммитить `appsettings.json` в публичные репозитории

- Первый запрос может быть медленным (инициализация)
- Локальные модели (Ollama) работают быстрее, но требуют мощного ПК
- Облачные модели зависят от скорости интернета
