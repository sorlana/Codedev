# Руководство по использованию C# Refactoring Assistant

## Как работать с приложением

### 1. Создание диалога

1. Введите путь к вашему C# проекту в поле "Путь к проекту C#"
2. Нажмите "Создать диалог"
3. Приложение инициализирует Git репозиторий (если его нет) и активирует проект в Serena

### 2. Отправка команд ИИ

В поле ввода внизу экрана вы можете отправлять команды на естественном языке. Вот примеры:

#### Примеры команд для рефакторинга:

**Просмотр кода:**
- "Покажи мне содержимое файла Program.cs"

- "Покажи методы класса UserService"
- "Найди все места, где используется метод GetUser"

**Рефакторинг:**
- "Переименуй метод GetUserData в FetchUserInformation"
- "Извлеки этот код в отдельный метод"
- "Добавь проверку на null в метод ProcessOrder"
- "Оптимизируй цикл в методе CalculateTotal"

**Создание кода:**
- "Создай новый класс OrderService с методами Create, Update, Delete"
- "Добавь метод валидации email в класс UserValidator"
- "Создай интерфейс IRepository с базовыми CRUD операциями"

**Анализ кода:**
- "Найди все TODO комментарии в проекте"
- "Покажи все публичные методы в классе ProductController"
- "Найди дублирующийся код в проекте"

**Работа с файлами:**
- "Покажи структуру папки Services"
- "Создай новый файл appsettings.Development.json"
- "Удали устаревшие файлы в папке Migrations"

#### Примеры команд для агентского режима:

- "начни выполнение задач из .kiro/specs/auth/tasks.md" - с указанием пути
- "execute tasks from tasks.md" - английский вариант
- "запусти выполнение задач" - краткий вариант
- "выполни задачи из tasks.md" - альтернативный вариант

**Управление выполнением:**
- "останови выполнение" - остановить текущее выполнение
- "stop execution" - английский вариант

- "продолжи выполнение" - возобновить выполнение
- "resume execution" - английский вариант

**Проверка статуса:**
- "покажи статус выполнения" - показать текущий прогресс
- "show execution status" - английский вариант

### 3. Работа с чекпоинтами

Приложение автоматически создает Git чекпоинты перед каждым изменением кода:

- **Автоматические чекпоинты**: Создаются перед каждой командой ИИ
- **Откат**: Нажмите "Откатить" на любом чекпоинте в правой панели
- **История**: Все чекпоинты сохраняются с описанием команды

### 4. Агентский режим выполнения задач

Агентский режим позволяет автоматически выполнять последовательность задач из файла `tasks.md` прямо через чат.

#### Как использовать:

1. **Создайте файл tasks.md** в корне вашего проекта или в подпапке (например, `.kiro/specs/feature/tasks.md`)

2. **Запустите выполнение** через команду в чате:
   ```
   начни выполнение задач из tasks.md
   ```
   или с указанием пути:
   ```
   начни выполнение задач из .kiro/specs/auth/tasks.md
   ```

3. **Наблюдайте за прогрессом** в реальном времени:
   - Индикатор прогресса показывает текущий статус (🔄 Выполняется... 3/10 задач)
   - Сообщения о каждом шаге появляются в чате
   - Кнопка "Остановить" позволяет прервать выполнение

4. **Управляйте выполнением**:
   - Нажмите кнопку "Остановить" или напишите `останови выполнение`
   - Для продолжения нажмите "Возобновить" или напишите `продолжи выполнение`
   - Проверьте статус командой `покажи статус`

#### Визуальные элементы:

**Индикатор прогресса:**
- 🔄 Выполняется... (3/10 задач) - идет выполнение
- ⏸️ Приостановлено (3/10 задач) - выполнение остановлено
- ✅ Завершено (10/10 задач) - все задачи выполнены
- ❌ Ошибка - произошла ошибка

**Кнопки управления:**
- **Остановить** (красная) - останавливает выполнение после текущей задачи
- **Возобновить** (зеленая) - продолжает выполнение с места остановки

**Сообщения о прогрессе:**
- 🤖 Начинаю выполнение задачи...
- 📌 Создаю чекпоинт...
- 🧠 Отправляю задачу в LLM...
- ✅ Задача выполнена за X.Xс
- 📝 Обновляю статус задачи в файле
- ❌ Ошибка: [описание]
- 🎉 Все задачи выполнены успешно!

#### Формат файла tasks.md:

```markdown
# План реализации: Моя функция

## Задачи

- [ ] 1. Первая задача
  - [ ] 1.1 Подзадача 1.1
  - [ ] 1.2 Подзадача 1.2

- [ ] 2. Вторая задача
  - [ ] 2.1 Подзадача 2.1

- [ ]* 3. Опциональная задача (пропускается)

- [ ] 4. Checkpoint - Контрольная точка

- [ ] 5. Финальная задача
```

**Типы задач:**
- `- [ ]` - обычная задача
- `- [x]` - завершенная задача (пропускается)
- `- [ ]*` - опциональная задача (пропускается)
- Задачи с "Checkpoint" - останавливают выполнение для подтверждения

### 5. Управление диалогами

- **Выбор диалога**: Кликните на диалог в левой панели
- **Удаление диалога**: Наведите на диалог и нажмите 🗑️
- **Несколько проектов**: Можно создать отдельные диалоги для разных проектов

### 6. Настройка моделей ИИ

Нажмите кнопку ⚙️ в левой панели для настройки:

#### Вкладка "Provider" (Облачные модели):
- **Base URL**: URL API провайдера (например, `https://api.openai.com/v1`)
- **API Key**: Ваш API ключ
- **Model Name**: Название модели (например, `gpt-4`, `deepseek-chat`)

Поддерживаемые провайдеры:
- OpenAI (GPT-4, GPT-3.5)
- DeepSeek
- F5AI
- Любой OpenAI-совместимый API

#### Вкладка "Local" (Локальные модели):
- **Ollama URL**: URL вашего Ollama сервера (обычно `http://localhost:11434`)
- **Model**: Выберите модель из списка (нажмите "Refresh Models")

Популярные модели Ollama:
- llama2
- mistral
- codellama
- deepseek-coder

### 7. Тестирование подключения

После настройки модели:
1. Нажмите "Test Connection"
2. Дождитесь результата
3. Если тест успешен, нажмите "Save"

## Советы по использованию

### ✅ Хорошие практики:

1. **Будьте конкретны**: "Переименуй метод GetUser в FetchUserData" лучше, чем "Измени метод"

2. **Указывайте контекст**: "В классе UserService переименуй метод..." лучше, чем просто "Переименуй метод..."

3. **Проверяйте изменения**: После каждой команды проверяйте результат в вашей IDE

4. **Используйте чекпоинты**: Если что-то пошло не так, откатитесь к предыдущему чекпоинту

5. **Разбивайте задачи**: Лучше несколько простых команд, чем одна сложная

### ⚠️ Ограничения:

1. **Windows команды**: Приложение автоматически конвертирует Linux команды в Windows, но лучше использовать Windows синтаксис:
   - `dir` вместо `ls`
   - `type` вместо `cat`
   - `copy` вместо `cp`

2. **Пути к файлам**: Используйте относительные пути от корня проекта

3. **Большие изменения**: Для масштабных рефакторингов лучше разбить на несколько шагов

4. **Тестирование**: Всегда тестируйте код после изменений

## Устранение неполадок

### Ошибка "Git command failed"
- Убедитесь, что Git установлен и доступен в PATH
- Проверьте права на запись в папку проекта
- Удалите диалог и создайте новый

### Ошибка "Error executing shell command"
- Проверьте, что команда корректна для Windows
- Убедитесь, что путь к проекту правильный

### Ошибка подключения к Ollama
- Убедитесь, что Ollama запущен: `ollama serve`
- Проверьте URL: обычно `http://localhost:11434`
- Попробуйте обновить список моделей

### Ошибка API ключа
- Проверьте правильность API ключа
- Убедитесь, что у вас есть доступ к API
- Проверьте баланс аккаунта (для платных API)

### Проблемы с агентским режимом

**Файл tasks.md не найден:**
- Убедитесь, что файл существует в корне проекта
- Если файл в подпапке, укажите относительный путь: `.kiro/specs/feature/tasks.md`
- Не используйте абсолютные пути (C:/...), только относительные от корня проекта

**Команда не распознается:**
- Используйте точные формулировки: "начни выполнение задач из tasks.md"
- Попробуйте английский вариант: "execute tasks from tasks.md"
- Проверьте, что команда написана без опечаток

**Выполнение не запускается:**
- Проверьте формат файла tasks.md (должна быть секция `## Задачи`)
- Убедитесь, что есть незавершенные задачи с чекбоксами `- [ ]`
- Проверьте статус командой `покажи статус` - возможно, выполнение уже запущено

**Выполнение останавливается с ошибкой:**
- Прочитайте сообщение об ошибке в чате (начинается с ❌)
- Проверьте, что LLM API доступен и работает
- Убедитесь, что проект является Git репозиторием
- Попробуйте возобновить выполнение: `продолжи выполнение`

**Кнопки управления не отображаются:**
- Обновите страницу браузера (F5)
- Откройте консоль браузера (F12) и проверьте наличие ошибок JavaScript
- Убедитесь, что выполнение действительно запущено командой `статус`
- Проверьте, что вы находитесь в правильном диалоге

**Индикатор прогресса не обновляется:**
- Подождите 2-3 секунды - система обновляет статус каждые 2 секунды
- Проверьте подключение к интернету
- Обновите страницу браузера
- Откройте консоль браузера (F12) и проверьте наличие ошибок сети

**Сообщения о прогрессе не появляются:**
- Система обновляет сообщения автоматически каждые 2 секунды
- Обновите страницу браузера
- Проверьте, что диалог активен (выбран в левой панели)
- Убедитесь, что выполнение действительно запущено

**Выполнение "зависло":**
- Проверьте статус командой `покажи статус`
- Если статус "running", подождите - задача может выполняться долго
- Если прошло более 5 минут, остановите выполнение: `останови выполнение`
- Проверьте логи в консоли приложения на наличие ошибок

## Дополнительная информация

### Где хранятся данные?
- **База данных**: `refactoring.db` (SQLite)
- **Конфигурация**: `appsettings.json`
- **Git репозитории**: В папках ваших проектов

### Безопасность
- API ключи хранятся в `appsettings.json`
- API ключи маскируются в интерфейсе
- Рекомендуется не коммитить `appsettings.json` в публичные репозитории

### Производительность
- Первый запрос может быть медленным (инициализация)
- Локальные модели (Ollama) работают быстрее, но требуют мощного ПК
- Облачные модели зависят от скорости интернета

## Поддержка

Если у вас возникли проблемы:
1. Проверьте логи в консоли приложения
2. Проверьте консоль браузера (F12)
3. Убедитесь, что все зависимости установлены (Git, .NET, Ollama)
4. Попробуйте удалить диалог и создать новый
